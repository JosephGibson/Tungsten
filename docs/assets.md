# Assets

Where each asset type lives and what its manifest entry needs. [AGENTS.md](../AGENTS.md) links here. A new asset type adds its row here in the change that adds its manifest section.

Every asset file is listed in a `manifest.json` and named in game code by its registry ID. `just repo-check` checks that each file under an `assets/` folder in this repository is listed and each listed path exists; loaders validate what the files contain. In a game's own repository, `tungsten check` loads every listed file and every unlisted `.json` file under the manifest's folder as a scene, so an unlisted image or sound goes unreported, and `tungsten package` ships it.

| Type | Location | Section | Required |
| --- | --- | --- | --- |
| Sprite | `assets/sprites/` | `sprites` | ID, filter `nearest`/`linear`; optional `normal_map` (a PNG the image's size, which makes the sprite lit, so lights and the ambient light shade it; without one it draws unlit), `emissive_mask` (a PNG the image's size, whose colour a lit sprite adds after its lights, uncoloured by its tint, showing where the image is opaque and fading with the tint's alpha), `nine_slice` (`[left, top, right, bottom]` in source pixels, for UI images; `D-148`) and `anchor` (`[x, y]` in source pixels: the point drawn at the entity's position, scaled with it and turned about; unset, the sprite draws from its top-left and turns about its centre) and `points` (`{ "<name>": [x, y] }` in source pixels, names `[a-z][a-z0-9_]*`: where `tungsten::core::sprite_point` reads a part as drawn, mirrored, scaled and turned with the sprite) |
| Sheet | `assets/sprites/` | `sheets` | ID, `path` (a PNG), `frame` (a cell's `[width, height]`); optional `count` (the first cells; every whole cell by default), `filter`, `normal_map` and `emissive_mask` (the image's size, cut as it is) `anchor` (in a frame's pixels) and `points` (`[x, y]` on every frame, or `[[x, y], …]` one a frame, a frame past the list without the point); its cells, left to right then top to bottom, register as sprites `<sheet>_<n>` from 0, which animations and prefabs name as sprites; a frame ID another entry takes, a `count` past the cells or a `frame` larger than the image fails the load |
| Animation | `assets/animations/` | `animations` | ID; sprite IDs must exist; a frame's optional `sound` names a sound ID, which plays as the clip enters that frame, a loop's wrap included (the kit's `animation` component plays it, and takes `speed` and `despawn`) |
| Boot group | manifest only | `boot` | optional `logo` and `bar` (sprite IDs) and `font` (a font ID), each in the merged graph, and `hold`, the seconds the boot shows at least from its first frame (finite, at least 0, none in a script run), set by one root at most; while the rest loads, boot frames draw the logo at the window's centre, the bar under it stretched to the load's progress and, with the font, `NN %` (`App::set_boot_view` replaces that view, as the template's splash does) |
| Font | `assets/fonts/<Fam>/` | `fonts` | ID |
| Font family | manifest only | `font_families` | family ID, `faces` (`fonts` IDs) (`D-115`) |
| Fallback chain | manifest only | `font_fallback` | a list of family IDs, not a map (`D-115`) |
| Sound | `assets/sounds/` | `sounds` | ID; optional `looping`, `volume` (finite, at least 0), `bus` (`"music"` or `"effects"`, effects by default) and `max_voices` (1 to 64, 64 by default); a sample rate of 1,000–384,000 Hz |
| Tilemap | `assets/tilemaps/` | `tilemaps` | ID; a Tiled `.tmj` with one embedded tileset whose tiles name sprite IDs in a `sprite_id` property, with optional tile properties `material` (a string, not empty), `health` (finite, above 0), `broken` (the sprite of the tile a broken cell becomes; needs `health`), `one_way` (a bool: in a collision layer, solid through its top face alone, from above), `slope` (a string: in a collision layer, the slope its cell is instead of a full box, its rise `45`, `2:1 low` or `2:1 high` and the corner its solid part holds, `br`, `bl`, `tr` or `tl`, as `"45 br"`, solid below the diagonal from the bottom-left corner to the top-right; a `2:1 low` cell is a triangle half a cell high and a `2:1 high` one a trapezoid from half a cell to a cell, so the two side by side make one surface, and `tr` and `tl` are ceilings; not with `one_way`), `style` (its auto-tile style), `mask` (0 to 15, a variant's open sides: 1 up, 2 right, 4 down, 8 left; needs `style`, and a styled tile without one or a `slope` is the style's brush, one per style, while a styled `slope` tile without one is one of the style's slope tiles, its style to its neighbours' sides and never picked) and `weight` (at least 1, a variant's draw weight; needs `mask`), brushes resolved to their variants at load; tile layers (a `kind` property `collision` for collision, whose `layers` and `mask`, strings of comma-separated layer numbers 0 to 31, are the physics layers its tiles are in and meet, `"0"` and every layer when absent; a render layer's `z`, a whole number, draws it among the sprites, after every sprite of a lower `z_order` and before the rest, under every sprite when absent, its `unlit`, a bool, draws a lit tileset on the stock pipeline, and Tiled's own `tintcolor`, `#rrggbb` or `#aarrggbb`, multiplies into each tile's colour) and object layers, whose object classes name prefabs (`D-032`, `D-157`); under `World::spawn_area` a classed object with a Tiled name takes that name as its save identity in the area (`SaveId::authored`; names are unique across a game's areas), and one without spawns unsaved; a property of the wrong type or out of range fails the load |
| Shader | `assets/shaders/` | `shaders` | ID (`D-057`) |
| Material | manifest only | `materials` | `shader` ID, `uniform_defaults` (`D-058`); a shader with an `fs_main` and no `vs_main` is fragment-only and compiles after the engine's material prelude (the camera, texture and `material` bindings, the instance layout and a `vs_main` passing `uv`, `color` and the quad-local `local`, 0 to 1); `engine_glow`, the stock glow on shader `glow` (`v0` its colour, `f32s` its falloff, core boost, dither and peak alpha), and the 1 × 1 white sprite `engine_white`, which it and flat quads draw on, are reserved: a manifest material or sprite of either name fails the load |
| Post effect | manifest only | `post_effects` | `shader` ID, `uniform_defaults` (`D-308`): a game's own full-screen effect, drawn in the post stack as `PostPass::Custom`. `PostEffectRegistry::pass("<id>")` builds its pass with the defaults in its lanes (`vec4`, `f32s`, `i32s`), which a field or `set_vec4`, `set_f32` and `set_i32` change. The shader is a whole module on the stock post prefix ([below](#a-post-effects-module)); one whose shader is missing fails the load, and one whose module does not build is logged and left out of the frame |
| Physics layer | manifest only | `physics_layers` | a name, `[a-z][a-z0-9_]*`, and its layer, 0 to 31: `"physics_layers": { "walls": 3 }`; a name or a layer given twice across loaded manifests fails the load; `rigid_body`'s `layers` and `mask` name layers by number or by name, checked against the World at load (`D-178`) |
| Physics material | manifest only | `physics_materials` | a name and its contact coefficients, each optional: `friction` (finite, at least 0), `restitution` (0 to 1) and `rolling` (finite, at least 0), 0 by default; unknown fields fail; `rigid_body`'s `material` names one, checked against the World at load, and its own `friction`, `restitution` and `rolling` stand over the material's (`materials` are the render's, `D-058`) |
| Particle | `assets/particles/` | `particles` | ID, `path`; a config: `sprite` (or a `render` of kind `mesh`), `max_alive`, `emission`, `lifetime` and `initial_velocity`, with optional curves, `gravity`, `drag_per_sec` and `tint`; optional `z_order` (the newborn's depth), `clip` (an animation ID the particle steps through by its age), `stretch` (seconds, at least 0: its length along its velocity grows by \|v\| × `stretch` px), `stop` (`{ "mask": [...] }`, layers by number or by `physics_layers` name: its life ends where its first velocity meets a body or tile on them), `attractor` (`{ "pull", "swirl" }` in px/s², toward the live emitter) and `start_color` (`{ "range": [a, b] }`, one draw between two colours, or `{ "by_direction": curve }` over the first velocity's angle in turns), multiplied into `tint`; a mesh particle refuses `z_order`, `clip` and `stretch` (`D-093`), and an unknown clip or layer name fails the load |
| Particle mesh | manifest only | `particle_meshes` | `vertices`, `indices` |
| UI theme | `assets/ui/themes/` | `ui_themes` | ID, `path`; a JSON object of optional fields over the built-in theme (`tokens`, `kinds`, `text_styles` by name, which alone take an `outline` (`color`, `width`), a `shadow` (`color`, `offset`) and a `shrink` in (0, 1], `sizes` by name in UI units, `sounds`' `focus`, `activate` and `back` sound IDs), colours `#rrggbb`, `#rrggbbaa` or a colour token's name (the ten, `scrim` and `raised`), each `line_height` finite and above 0, a `text` object's `letter_spacing` in em (`D-198`); reloaded live and re-applied to the tree following the ID (`D-148`) |
| UI screen | `assets/ui/screens/` | `ui_screens` | ID, `path`; a JSON object at `version` 1 holding `root`, a `screen` (a modal scrim and its card: `width`, `children`, `card`'s `layout` and `overrides`, `over`) or a `root` (`layer` `game` or `game_popup`, `modal`, `children`); child nodes by `kind`: `group`, `row`, `column`, `panel`, `label`, `heading` (`centred`), `display` (`style`), `note`, `small`, `prompt` (`template`), `button` (with `children`), `choice_row`, `toggle_row`, `slider_row` (`range`'s `min` below `max`, `step` above 0; `readout`), `tab_rail` (`tabs`' `key` and `caption`), `meter` (`width`, `height`, `color`), `mount` and `repeat` (`key`, `rows`, `row`); every node's optional `key` (no `/`, unique in the file, a repeat row's within the row), `layout`, `overrides` (a theme kind's, colours resolved against the tree's theme at build), `style`, `mono`, `danger`, `bind` (`text`, `value`, `fill`, `visible`, `enabled`) and, on a control, `on` (`"pop"`, `push`, `action` or `setting`); a text node takes one of `text`, `bind.text` and, in a repeat's row, `field`; lengths in UI units, a size name or `spacing.xs`–`spacing.xl`; unknown fields fail with their path |
| Tileset | `assets/tilesets/` | `tilesets` | ID, `path`; a JSON object at `version` 1 holding `tiles`, each a tile named by its `sprite` (at most once in a tileset, since saves restore a cell's tile by its sprite) with the Tilemap row's tile properties (`material`, `health`, `broken` naming a tile by its sprite, `one_way`, `style`, `mask`, `weight`, `slope`) and `whole` (drawn at its sprite's own size from its cell's bottom-left); every room on it shares it; `tungsten schema tileset` prints its JSON Schema |
| Room | `assets/rooms/` | `rooms` | ID (`[a-z][a-z0-9_]*`; its map's ID, so a `tilemaps` entry cannot take it), `path`; a JSON object at `version` 1 holding `cell` (pixels), `size` (cells, 1 to 4,096 an axis), `tileset` (a `tilesets` ID, needed once a layer exists), `layers` (each `render`, with `z`, `unlit` and `tint`, or `collision`, with physics layer names in `layers` and `mask`; `cells` override a cell's tile by its sprite, `null` for empty), `shapes` (a `rect`, a `polygon` of 0°, 90°, 45° and 2:1 edges, whose sloped cells take the style's slope tiles for a brush, or a `line` of cells, each a `tile` or `null` into the layers it names), `objects` (a `prefab` `at` cells, its `set` dotted paths into its components, `on` the shape it rests on, `generator` the generator that made it, which a hand edit through the commands drops), `places` (a `point`, a `rect` or a `route` of points and point IDs, `to` linking a point or an area to `<room>.<place>`, `by` naming a route's mover) and optional `post`, `ambient` and `budget` (`lights`, 16 by default, and `objects`, 1,024); unknown fields fail, each error naming its field's path; `World::spawn_room` spawns it as an area; `tungsten schema room` prints its JSON Schema; [levels](levels.md) is the guide to making, editing and checking one, [the level rules](levels.md#findings) included |
| Prefab | `assets/prefabs/` | `prefabs` | ID, `path`; a scene entry's fields without `transform`: `sprite` (its `asset_id` and each variant checked at load, a misspelt one failing with the nearest name; its `color` a linear RGBA tint, 0–255 a channel, which the frame encodes to sRGB), `visible`, `tag`, at most one tween and `components` by registered name, unknown keys failing; `extends` names a base prefab, the file's fields replacing the base's resolved ones and its `components` merging member by member (objects recursively, arrays and scalars replaced), resolved again at every load's commit so a base's reload reaches its variants, a missing base or a cycle failing the load, `tungsten describe <prefab>` printing the result; `scale` (`[x, y]`, each finite and above 0, `[1, 1]` by default) is its spawn's `Transform.scale`; `sprite.variants` lists sprites a spawn shows in `asset_id`'s place, each a loaded sprite ID, one picked a spawn from the pool of `asset_id` and its variants by the spawn's save identity once it has one (a room object's name), else by its position's whole pixels, so a named or saved spawn shows the same one after a load with nothing saved (a scene entry's sprite takes none); `support` (`ground`, `under` or `wall`) has the level rules judge a room's prop by its sprite's drawn box, the variant its name picks at the prefab's `scale`: `ground` on solid within 2 px under 60 % of its bottom edge, sunk no more than 6 px, `under` within 2 px of a ceiling over 60 % of its top edge, `wall` within 3 px of a side over 60 % of its rows; checked at load against the World (`D-157`), with the data entries (`D-171`) |
| Data entry | `assets/data/`, a folder per kind by convention (`assets/data/effects/`) | `data` | kinds, each an object of entries by ID, each with `path`: `"data": { "<kind>": { "<id>": { "path": … } } }`; a JSON file of the type a plugin registered for the kind, a key repeated at any depth failing; loaded with the prefabs in two phases and checked against the World, so a prefab or an entry may name any other; reloaded live (`D-171`) |

- Example-local assets: `examples/NN_name/assets/` with its own `manifest.json`. IDs are unique across loaded manifests; duplicates are fatal.
- A data entry's ID is unique within its kind, across loaded manifests: two kinds, or a kind and `prefabs`, may share an ID. One file backs at most one prefab or data entry, since an edit reloads one (`D-171`).
- Template-local assets: `templates/<name>/assets/` with its own `manifest.json`, the only root a game made from the template loads (`D-123`). Layer 1 loads each template manifest on its own, outside the examples' uniqueness merge, and `just repo-check` covers its files as it covers an example's. Files outside `assets/`, such as the template's Windows icon in `windows/`, are no assets: they take no manifest entry and the archive does not ship them (`D-199`).
- `font_fallback` chains concatenate in root order, each family keeping its first position. A family's faces and a chain's families may come from another root: references are checked on the merged graph (`D-089`).
- Font ID `engine_mono` is reserved for the engine font, `tungsten::ENGINE_FONT_ID`, which the HUD, the systems overlay and the inspector draw with (`D-123`), and `engine_mono_semibold` for its SemiBold face, the family's weight 600 for the debug views' titles and headers (`D-168`). A manifest `fonts` entry under `engine_mono` replaces the Regular face for engine text; beside another face of the same family, weight and style with other bytes, the earlier face draws and a warning names both. Manifests are not checked against the reservation.
- Game code uses registry IDs; explicit scene loading follows `D-046`.
- Example 01's `assets/` is generator output, its accepted families locked by hash (`D-223`) and its actors' bodies data beside their sprites; [its authoring guide](../examples/01_platformer/tools/README.md) covers the families, the locks and the bodies.

## Coverage exceptions

Asset coverage exceptions are explicit: complete font families and their inventory README; four vendored LYGIA helper fragments and their license; and the fixtures crate's explicitly loaded `scene.json` (`D-046`). A new exception needs review in the checker (`ASSET_EXCEPTIONS` in `scripts/check-repo.py`), not a broad ignored extension.

## A post effect's module

A `post_effects` entry's shader is a whole WGSL module, `vs_main` and `fs_main`, that opens with the prefix every stock post effect opens with: the 96-byte block of the pass's lanes, the frame before the pass and its sampler, and a full-screen triangle.

```wgsl
struct Params {
    v0: vec4<f32>,
    v1: vec4<f32>,
    v2: vec4<f32>,
    v3: vec4<f32>,
    f: vec4<f32>,
    i: vec4<i32>,
};

@group(0) @binding(0) var src: texture_2d<f32>;
@group(0) @binding(1) var src_sampler: sampler;
@group(1) @binding(0) var<uniform> params: Params;

struct VertexOutput {
    @builtin(position) position: vec4<f32>,
    @location(0) uv: vec2<f32>,
};

@vertex
fn vs_main(@builtin(vertex_index) vi: u32) -> VertexOutput {
    var uv = vec2<f32>(f32((vi << 1u) & 2u), f32(vi & 2u));
    var out: VertexOutput;
    out.position = vec4<f32>(uv * 2.0 - 1.0, 0.0, 1.0);
    out.uv = vec2<f32>(uv.x, 1.0 - uv.y);
    return out;
}
```

`Params`' `v0` to `v3` are the pass's `vec4` lanes, `f` its `f32s` and `i` its `i32s`. The pass replaces every pixel of its target with what `fs_main` returns, with no blending. The block does not grow: a pass binds 256 bytes there, and a module whose block at group 1, binding 0 is larger is refused at its load, its effect left out of the frame.

A module may mark one section, which lets the engine draw the effect in one pass with the stage beside it (`D-307`): the lines between `// @fx begin <class>` and `// @fx end`, holding one function and its helpers, every function, constant and struct named `<id>_…` after the effect's manifest ID. `fs_main` calls that function and adds nothing to it.

| Class | The function | It may |
| --- | --- | --- |
| `mix` | `fn <id>_fx(color: vec4<f32>, uv: vec2<f32>, p: Params) -> vec4<f32>` | scale each colour channel of `color` by a factor from 0 to 1 and add a constant from 0 up, neither following the colour, and return `color.a` as it came |
| `pixel` | `fn <id>_fx(color: vec4<f32>, uv: vec2<f32>, p: Params) -> vec4<f32>` | compute anything from `color` that is continuous in it |
| `steps` | `fn <id>_head(uv: vec2<f32>, p: Params) -> vec4<f32>` | sample `src` at `uv` and quantise or branch on it |
| `head` | `fn <id>_head(uv: vec2<f32>, p: Params) -> vec4<f32>` | sample `src` anywhere |

A `mix` or `pixel` function names nothing outside the section but `Params`: no `src`, no `params`. A `steps` or `head` function samples `src` and reads the block through its `p`, never `params`. A section holds no entry point. A `mix` that ends the stack draws in the pass of the stage before it, when that stage has a section too; the other classes only lead such a pass. Under `render.hdr` whole runs draw in one pass, and a `pixel` function may then follow another stage, on a colour no 8-bit target clamped between them. A section is read only from a module that holds the prefix above byte for byte, since a fused pass draws the section on the engine's copy of it. The engine checks the markers, the names, the signature, what a section may name, and that a `mix` returns `color.a` on every path, as the last component of the `vec4<f32>` it returns, and reads `color` only for its colour channels. It cannot check the rest of a `mix`'s promise: one that amplifies a channel, subtracts from it or follows the colour can differ from its own unfused pass by more than one 8-bit step. A section the engine refuses is logged and the effect draws in a pass of its own, as a module without a section does, and as an effect whose ID is a stock effect's does.

```wgsl
// @fx begin mix
fn tint_fx(color: vec4<f32>, uv: vec2<f32>, p: Params) -> vec4<f32> {
    let amount = clamp(p.f.x, 0.0, 1.0);
    let tint = clamp(p.v0.rgb, vec3<f32>(0.0), vec3<f32>(1.0));
    return vec4<f32>(color.rgb * mix(vec3<f32>(1.0), tint, amount), color.a);
}
// @fx end

@fragment
fn fs_main(in: VertexOutput) -> @location(0) vec4<f32> {
    return tint_fx(textureSample(src, src_sampler, in.uv), in.uv, params);
}
```
