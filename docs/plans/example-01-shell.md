## 2. Design

### 2.1 Scope, order and the tests

Fifteen rows, nine steps and the close. The order follows what each needs:

- Step 1 first: Steps 4, 5 and 8 each fail without one of its fixes (A12).
- Step 2 before Step 8: a reset calls no `on_resume`, so a hand pause would outlive a load from pause.
- Step 4 before Step 6: the engine's apply gives an unset UI scale `tungsten.json`'s, or 1.0.
- Steps 6 and 7 before Step 8: with Bloom the engine's switch and game over's passes in `PostTail`, a change of run's swap has no stack to put back; the stopped tree needed a `swap` and a Bloom restore in `shell_save` for it.
- Step 9 after Step 8: `ModalScreen::adopt` raises the engine's toasts over each screen as it opens, which the shell's tick did by hand.
- Steps 2 and 3 need nothing; Step 5 needs Step 1 alone.

A test's asserts stand. A step may port a test's reads or its setup to the new owner (a switch written where an option was, the drawn stack read where `PostStack` was, a window played where none takes a request), and changes an asserted value only where its Moves name it. A test whose subject a step removes goes with it, named in the Moves. New tests are the done-when's alone.

Each shell step edits `T/src/shell/` and copies the changed files over `E/src/shell/` (`cp`); 01's theme comes from its generator (Step 5). The probes are the steps' starting material: Step 1 is `W/step1.patch`, Step 2 `W/edits/s2.py`, Step 3 `W/step3-stars.patch`, and Steps 4 to 9 the prototype's stages 3 to 8 (their deltas and `W/edits/`), each with the tests and records its done-when names.

### 2.2 The engine's four parts (Step 1)

- **The confirm closes on any first answer.** `Confirm` keeps an `answered` flag; `answer` returns when it is set, runs the chosen answer's callback when it has one, drops the other's, and pops when the screens are idle after it. So Stay, Cancel and Keep close their dialogs, and an answer whose callback left a request waiting (a reset) still leaves the dialog to it.
- **The theme before the update.** `App` calls `apply_configured_theme` after `stage_time` and before `stage_update`, as well as after the hot reload: one `Option` read a frame once applied.
- **The router copies no name unheard.** `play_menu_sounds` returns when nothing was heard, before it builds its list.
- **The countdown names the answer it takes.** The count's line reads `<the safe answer's caption> in <n> s`, as `Revert in 10 s`: `count_text` takes the dialog's `no`. No public item moves.
- **Moves:** an answer with no callback closes its dialog; a theme `tungsten.json` names is on for the first frame's update; a confirm's countdown line gains the answer's caption. Known issues lose the three rows.

### 2.3 01's run on the stack's hold (Step 2, S-157)

- `GameplayState` returns `true` from `holds_clock` and loses its `on_pause` and `on_resume`. The stack's hold and `Time::pause` both take effect from the next frame, set in the same dispatch (A4), so no frame's dt moves.
- A test's own `Time::pause` is no longer undone when a screen over gameplay closes; no test leans on that (A12).
- **Moves:** under a covering screen `Time::is_held()` is true and `is_paused()` false; `player.rs:373` reads the hold.

### 2.4 The title's stars under a cover (Step 3, S-157)

- `title::sky` adds a frame's real dt to its clock only while the title is on top. A star in flight under a cover still flies and ends on the game clock, which the title does not hold.
- **Moves:** after a cover the next star comes within `METEOR_EVERY` of on-top time, not at once, and none follow back to back. Known issues lose P3.

### 2.5 The UI's numbers and theme in `tungsten.json` (Step 4, S-123, S-139)

- Both games' `tungsten.json` gain `"ui": { "theme": "shell", "reference_height": 720, "min_viewport": [731, 411], "scale": 0.75, "hud_corner": "top_right" }`.
- The shell's plugin keeps `hud.enabled = false` and loses the `ScaleFactor` block and the corner; the shell's `apply_settings` loses its unset-scale lines; `theme.rs` loses `REFERENCE_HEIGHT`, `UI_SCALE`, `MIN_VIEWPORT` and `apply`, and the title its call. Settings reads an unset UI scale as the scale applied, `ScaleFactor::ui_scale()`.
- Tests read the numbers from `Config` (a `shipped_ui_scale()` helper in the template's `main.rs`).
- **Moves:** none in play: the same numbers from the file, on by the first frame's update (Step 1).

### 2.6 The router's parts (Step 5, S-109, S-133, S-187)

- **Menu sounds:** the theme file gains `"sounds": { "focus": "ui_move", "activate": "ui_select", "back": "ui_back" }` after `sizes`; `menu_sounds`, its call and `theme::MENU_SOUNDS` go. 01's theme is its generator's copy: the content family's run writes the line. The shell's handlers already close on a Back button's `Activated` or `Cancel`.
- **Slider commits:** `SettingsView::held` goes. A scale applies on `ValueCommitted`, every other value on `ValueChanged`; the readout shows the dragged slider's own value, found through `UiRouter::captured`.
- **The capture's timeout:** `capture_next_input_for(cell, CAPTURE_SECS)`; the prompt's seconds come from `capture_remaining()`, and the state's `Timer` goes.
- **Moves:** none asserted. The focus sound follows the router's `moved_focus` where the shell read a navigation press.

### 2.7 The options in `Settings` (Step 6, S-118, S-145, S-50)

- **The options.** `GameOptions` keeps `pause_unfocused`, `damage_numbers`, `autosave` and `screen_shake` and stays a `World` resource, the live copy: `Settings::game` deserializes on every call and 01 reads the options each step. `options::load` reads it once from `Settings::game::<GameOptions>()`; `options::save(&mut World)` sets the section, then saves `Settings`, and `settings::save` calls it. `OptionsStore` and the second `SaveSlots` go.
- **The two switches.** The Bloom and mute toggles bind and write `Settings::bloom` and `Settings::mute_unfocused` through `change`. Display's Reset unsets Bloom, Audio's the mute, and Gameplay's replaces `GameOptions` whole. `Shell::focus_muted`, the zero-volume copy and `shell::apply_settings` go; its callers call `tungsten::apply_settings`. `focus` keeps the pause.
- **The old file.** While `Settings` hold no game section (`game::<Option<IgnoredAny>>()` is `None`), `options::load` reads `<user>/options/options.json` through a private `OldOptions` (the six old fields, schema 1). Bloom off and the mute on go to the switches, the rest to the section, and `Settings` saves at once. The file stays and is not read again.
- **The post stack, for now.** `post` keeps game over's tail alone: the Bloom take-out, `Post::kept`, `Post::left` and the clone go. Bloom off is the engine's: the frame draws without it and the game's `PostStack` stands.
- **01.** `bloom_on` reads `Settings::bloom() != Some(false)`. Its two Bloom tests write the switch, and the one that read `PostStack` reads the drawn stack (`Harness::draw`).
- **Tests.** The template's Bloom test becomes `the_bloom_option_writes_the_engine_switch`: the drawn stack loses Bloom while off, `PostStack` stays the game's, Display's Reset unsets the switch, a restart keeps it. Three tests of the shell's take-out go with it (`bloom_off_then_a_run_change_restores_nothing_the_game_dropped`, `a_stack_that_outlives_its_run_keeps_its_bloom`, `a_stack_set_to_its_stripped_value_keeps_its_withheld_bloom`); the engine's own hold the drawn stack (`bloom_off_drops_bloom_from_the_drawn_stack`, `an_empty_tail_with_bloom_on_draws_the_game_stack_itself`). The options' store test becomes `options_live_in_settings_game_section_and_a_bad_one_falls_back`; new `the_old_options_file_is_adopted_once`, which changes every field of the old file before its second start. The two mute tests and the per-tab Reset test write and read the switches, their expected values unchanged.
- **Moves:** the options live in `settings.json`'s `game`; `<user>/options/` is read once and never written; a game section that does not read warns in the log and defaults, where a damaged options file toasted; `shell::apply_settings` is gone, and `options::save` and `settings::save` take `&mut World`. 01's pit, §2.11.

### 2.8 The post tail and the display (Step 7, S-50, S-120, S-147)

- **Game over's passes.** `shell_frame` rewrites `PostTail` in place while game over shows, from its first frame, and `GameOverState::on_exit` clears it, so the resource the app inserts stays (the prototype inserted and owned one, which the stack removed for good); `passes` returns `[PostPass; 2]`. `Post`, `post` and `Shell::post` go.
- **The display keys.** `display_keys` goes: the engine's F11 and F9 write and save `Settings` (A4).
- **The display read.** `settings::display` goes for `tungsten::requested_display`. Once a windowed size was sent, it gives the live size (`D-169`). Headless no window takes a request, so the two tests that read the Window size row after Apply and Keep play the window: a `grant_size` helper writes the set size into `DisplayState` and steps a frame, before the same assertions.
- **01's** game-over test reads the drawn stack under game over, where `PostStack` no longer holds the passes; its assert lines stand.
- **Moves:** `PostStack` is the game's alone, never edited by the shell; after a hand resize the Window size row shows the size the window runs at, where it showed the set one.
