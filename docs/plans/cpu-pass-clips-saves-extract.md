### 2.2 How a step is judged

- **Before a step:** `just preflight docs/plans/cpu-pass-clips-saves-extract.md --step N`; a hit outside the step's list is read before editing.
- **Step sitting.** With the step's change in the tree, uncommitted, and nothing beside it: `WGPU_BACKEND=vulkan just perf sitting --base HEAD --rows <the step's rows> --cpu-only --wait-quiet 600`. The owner's remote-desktop client stays disconnected; never `--allow-background` for a judged sitting.
- **Reading a sitting.** A row's judged pairs are A1→B1 and A2→B2, or A3→B3 and A4→B4 where `sitting.json` marks the row `reran`. `python3 -B perf-runs/714-cpu-pass/tools/judged.py <sitting> perf-runs/714-cpu-pass-2/step-N` prints each pair's digest line and metrics. A B capture named for a target is a judged pair's.
- **Done-when and target are two things.** A done-when lets the step commit: its tests, the pins it may move, the outputs it may not, a sitting in which its metric fell by its bound and nothing regressed. Its **Target** line is the item's reading against §2.1, quoted in the evidence log.
- **An item's end** (`phase-7.md` §2.5), read on the last of its steps that landed:
  - `done`: the target is met in both judged B captures; for C6, by the control's reading on the landed tree.
  - `stopped`: the target is missed, every step of the item landed or was taken back because its own metric did not fall by its bound (a lever tried and refuted, its numbers in [benchmarks.md](../perf/benchmarks.md#levers-for-92)), and a profile on the landed tree (a gated one of the row's window; for C6, of the control's run) shows what remains is the work §2.3–§2.5 name for the item. The evidence row quotes the profile's split.
  - `open`: a step of the item ended for any other reason (a failed test, a pin outside its Moves, a file outside its list). Step 14 then stays open and the close hands off a re-plan of that step.
- **Exact means checked.** Steps 2, 3 and 4 keep every output bit for bit, and Step 6 keeps every restored World: each lands a test that runs the old path beside the new (a `#[cfg(test)]` reference) over seeded inputs and compares every output, with a negative control that the test fails when the new path drops one case.
- **Pins.** A pin is in a step's list where the step may move it, and its Moves line says how. Rewrite one with `TUNGSTEN_GUARDS_WRITE=1` on that test, then run it twice. `python3 -B perf-runs/20261121-cpu-pass-plan/tools/pins_fell.py HEAD <pins>` passes when only `allocations` and `allocated_bytes` differ from the last commit's and neither is higher.
- **Profiles**, where an item misses its target: `python3 -I perf-runs/20261110-cpu-stress/tools/gated_profile.py target/perf/tree-aligned/release/example-02-bench bench:<bench>:<preset>:<warm-up + 300> perf-runs/714-cpu-pass-2/step-N <label> 0-299 5000` with `WARMUP=<the row's>`, then `perf script -F ip,sym --no-inline` and `python3 -I perf-runs/20261110-cpu-stress/tools/fold.py <dump> 300 5000 <root>`, the root `particles::animate_sprites` or `saves::save_snapshot`. For C6: `perf record -e cycles:u -c 1000003 --user-callchains --call-graph fp -o <out> -- <the control's test binary> the_extract_headless --ignored`, the same with `instructions:u`, each `extract_into` sample a million events over 360 frames of 400,000 sprites, and `perf annotate --stdio --no-source -s tungsten::sprite_extract::extract_into` for the loop's split.

### 2.3 C3: the clip's slot

From the prototype (A5, A6); `patch -p1 < target/plan-wip/7.14b-probes/c3-clip-slot.patch` applies to `326b0ee0`.

- **The registry** keeps its clips in a list in registration order, each with its ID, beside a map from ID to slot and a map from source path to slot, both on `BuildHasherDefault<DefaultHasher>`, which takes no room in the map. `insert` gives a new ID the next slot and a held ID its slot with the new data, so a slot never moves. `get`, `id_for_path`, `insert` and `insert_with_path` answer as today; `iter` and `ids` go in registration order, where they went in the hash's.
- **The state** keeps `slot: u32`, private, none until its first lookup. A lookup takes the clip at the slot when that slot's ID equals `animation_id`, else looks the ID up by name and keeps the slot it finds. The public `animation_id` stays a `String` any caller may write, in place too, so the compare is of the bytes: the lengths, then eight bytes at a time and the last eight, with no call.
- **`frame_index` narrows to `u32`**, which pays for the slot: the state stays 40 bytes. A clip holds fewer than 2^32 frames. `Advanced::sound_frame` stays a `usize`.
- **`#[inline]`** on `advance`, `advance_entering`, `advance_in` and `current_sprite`: without it the lookup's gain stops at 0.12 ms (A5).
- **Exactness.** Every lookup returns the clip `get(&animation_id)` returns, whatever the slot holds: a state whose ID was reassigned, rewritten in place, cloned from another, advanced against another registry or left from before a clip was replaced. The kit's `animation_tick` keeps its last-clip memo and its results.

### 2.4 C6: the extract's row loop

- **The plain loop** (Step 3, from `c6-plain-loop.patch`). An archetype with no override block and no flip takes a loop of its own over its four required columns, the parallax column chosen once an archetype, its running state (the last class, the last order, the order's bits, the cull count) in locals written back after the archetype. - **No key while a frame stays one class in painter order** (Step 4). Today every visible sprite writes a 16-byte key that only pass 2, the sort and a count change read. ### 2.5 C5: a prefab's runtime spawns as a table

Format 2. A capture of one World restores to the World the same capture restores to today.

- **A table** holds spawns of one area, one prefab and one set of saved components: its prefab, each column's component name and layout, the references its rows share, and a row a spawn, `[id, leaf, leaf, …]`. It sits in the area's `spawns` beside the records, as one element; in memory `spawns` holds an enum of a record or a boxed table, so `AreaSave` and a record keep their sizes (A11).
- **A column's leaves.** A component's saved form runs through a serializer that opens its structs, tuples, fixed arrays and newtypes in place and writes everything else as one leaf: the `Value` `serde_json::value::Serializer` builds for it (a number, a string, a unit variant's name, an `Option`'s `null` or whole value, a sequence, a map, an enum's tagged value). A layout is a column's field names in serialization order. Building the component's `Value` back from its layout and leaves gives exactly what `serde_json::to_value` gives.
- **Which spawns, in two walks.** The first walk reads no value: it counts each group of one area, prefab and component set and finds the group's lowest ID. A group of 16 or more opens a table on its lowest-ID spawn, whose leaves fix each column's layout and whose references (its own and those waiting on it) are the table's. In the second walk a spawn of the group joins the table when its references equal the table's and its cells fit the layout as they serialize; any other spawn is written as a record by today's path, which also reports its error as today's; a lowest-ID spawn that fails to serialize opens no table, so the walk reports the spawn it reports today. A table left under 16 rows is written back as records.
- **Order-free.** A spawn's place rests on the World's content alone (its group's count, its lowest ID's layout and references), never on the order archetypes or rows are walked: a World restored into other entity allocations and captured again writes the same bytes. Records and a table's rows each go by ID; tables follow the records, ordered by prefab and columns; two captures of one World are byte-equal.
- **No group a reference map.** Groups are found by the last spawn's group, then by a map keyed by area, prefab and set, so their number is bounded by those, and many spawns with references of their own cost what their records cost today. A spawn's references are read once, as today, and counted once.
- **Sixteen.** Under it a table's header costs more than it saves, and a small save reads as format 1's but for `format`: a person's save stays records until a prefab's spawns are many.
- **The registry** keeps a second function a registration beside the one to a `Value`: the saved form into leaves. `SaveOptions::new` and `form` build both; no signature changes.
- **Restore.** A table's row becomes the record it stands for (its components' `Value`s built back), then takes the record's path: migrate, check, prepare, spawn. An area's spawns apply in ID order across records and tables; an area of records alone keeps its file order, as today. `check_world` accepts formats 1 and 2 and refuses the rest.
- **Kept areas.** A kept table is checked as its records are: each row's components are built back, migrated where the column's version is older, checked, and dropped with the record's report line where the registry lacks the component. It is kept as the table it came as when nothing was migrated or dropped, else as the records that result. So `check_world` fails on a kept table's bad value before anything changes, as on a record's. The waiting references read a kept table's IDs.
- **A generator's `migrate`** sees records alone: the area's tables are expanded before the value is built. Its rustdoc says what it gets.
- **`save::expand_tables(world: &mut Value) -> Result<(), String>`**, public: rewrites a world save's tables as records in place, so a game's migration step, or a test that walks a capture, reads one shape. 01's tests call it in their `json` helper, and so keep walking records.
- **Exactness.** The reference walk the first plan kept (`capture_world_asking_every_component`, every spawn a record) is the oracle: a capture with its tables expanded is that walk's bytes, and a World restored from either captures the same again.
- **Not built** (S-35's gap): cells equal in every row written once; a slot file's rows on one line; a compact form for a status.
- **What remains, if the target is missed:** the named records' patches, the erased reads (a keyed `get` a component a spawn), the leaves' pushes, `to_vec`'s floats and the ID map.
