## 2. Design

### 2.1 Rule filters and limits (Step 1)

A `cue_rules` rule takes optional fields; the load checks each against its event and fails one the event cannot carry at `<i>.<field>`, as it fails a `kind` today (`react/cues.rs:1622-1628`):

- `periodic`: `true` passes a damage occurrence of a periodic request (a status's or effect's tick), `false` a blow; on `damaged_part`, `damaged` and `killed` (S-122, K1).
- `amount`: `{ "min", "max" }`, each optional and inclusive, over the occurrence's amount; on an event with one, every game event included; an occurrence without an amount fails it (S-41).
- `flags`: `{ "all", "any", "none" }` over the World's own `Flags`, read as a tag filter reads tags; a World without `Flags` has none set; names checked as tag names, not declared, as flags are not (S-165).
- `effect`: an `effects` entry ID, which the load checks; on `effect_applied` and `effect_expired`; an effect written in place passes no `effect` filter (S-56).
- `fresh`: on `effect_applied`, `true` passes a new instance or an instant effect's landing, `false` a stack or a refresh. `EffectApplied` gains `fresh` (`with_fresh`), which the resolve sets (A4; S-96).
- `ended`: on `effect_expired`, `EffectExpired.ended`'s reading: `false` an instance that ran out (its time, its intensity or its fuel), `true` one ended early (S-56's ran-out flag).
- `min_interval`: game seconds per subject: once a rule runs for a subject, it skips that subject until the interval passes, on the cue system's clock as `sound`'s interval is.
- `cap`: at least 1; at most this many runs of the rule a step.

The filters run after the event, tag and kind filters, the limits last, so an occurrence a filter turns away spends no interval or cap. A rule its limit holds is traced `Skipped` with its reason (no new `TraceKind`). The limits' state is the cue system's: a last run per rule and subject, dropped once the subject is gone or the interval has passed, swept at most once a game second; unsaved, as `sound`'s intervals are.

`Occurrence` packs its bits (periodic, crit, fresh, ended, and Step 5's absorbed) into one byte and its effect into an index of the step's ID list, whose strings it reuses, so it keeps its size, measured first by a scratch `size_of` and asserted after (A2).

`CueEvent::of(entity)`: an occurrence at its subject's point as the cue system reads it (`point_of`, `:2592`), a position that is not finite read the same, so a game's `CuesOnEvent<ContactBegan>` gives each begin's closing speed as the amount with no point (A17; S-41's contacts). An entity's own `cues` lists stay unfiltered (Q8). The template's `AGENTS.md` sentence "A reaction that needs a condition beyond a rule's tag filter is Rust." becomes "A reaction past a rule's filters is Rust." (27 bytes freed).

```json
[
  { "on": "damaged", "filter": { "all": ["team.player"] }, "periodic": false, "do": [{ "sound": "hurt" }] },
  { "on": "impact", "amount": { "min": 300 }, "min_interval": 0.25, "cap": 4, "do": [{ "prefab": "sparks" }] },
  { "on": "damaged_part", "flags": { "all": ["show.damage_numbers"] }, "do": [{ "label": {} }] },
  { "on": "effect_applied", "effect": "scared", "fresh": true, "do": [{ "sound": "yelp" }] },
  { "on": "effect_expired", "effect": "frozen", "ended": false, "do": [{ "prefab": "thaw_glints" }] }
]
```

### 2.2 Named game events and the controller's cue events (Step 2)

- `CueEvent::named(name)` and `CuesOnEvent::with_names(names, map)`: one registration brings event `E` in under each of `names`, each registered once and checked as `new`'s name is (`:1437-1452`). An occurrence runs the cues of the name it carries; one naming none of them, or no name, is skipped and logged once per name. `new(name, map)` stays, and its occurrence's own name, when set, must be `name` (S-39).
- Four kit cue events, each about the controller's entity at its feet (its collider's bottom centre: a jump's where its step began, a landing's where it ended), with no other: `jumped` (a ground or coyote jump), `air_jumped` (an air jump; its amount the stat amount it paid, 0 for a free one), `jump_refused` (a press in the air refused for its cost) and `landed` (grounded at a step's end after a step that was not; its amount the speed it fell at as the step began, in px/s). `PlatformerController::landed()` joins the flags, skipped in the saved form when off (A9; S-48).
- The controller's system pushes them to a kit list, a `CuesPlugin` resource whose capacity is reserved at its build; the cue system drains it each step after the kit's other events and before the game's. No `EventQueue`, so no `events_sent` from 01's six foes in its pit window (A16, Q2); a World without `CuesPlugin` pushes nothing. A game's Rust reads the controller's flags.
- `KIT_EVENTS` grows from 13 to 17, so the `cues` component describes four more events and the template's `AGENTS.md` names them (about 50 bytes, A15).

### 2.3 The listener, pan, loops and a shake's falloff (Step 3)

- `CueListener::following(entity)`: the cue system moves the listener to the entity's point at each run's start, before any occurrence; a gone entity leaves it where it was (S-154).
- `CueListener::with_pan(width)`: a cue sound `dx` from the listener plays at pan `clamp(dx / width, −1, 1)` through `play_panned`; without it, through `play_with` as today, so today's commands are equal byte for byte (P7-13's pan).
- `{ "shake": { "trauma", "near", "far" } }` (`CueAction::shake(t).with_falloff(near, far)`, `0 <= near < far`): the trauma whole within `near` of the listener, falling linearly to none at `far`, as 01's `falloff` (A6); without a listener, whole; the number form unchanged (S-121, Q12).
- Loops: `{ "loop": { "id", "volume", "fade" } }` (`CueAction::looping`) makes the subject want the manifest sound looping at its manifest volume times `volume`; `{ "stop": { "id", "fade" } }` (`CueAction::stop_loop`) ends the subject's want. The kit plays one voice per looping sound ID, as 01 keeps its hums and crackle (A19), so its own loops never pass a sound's `max_voices` or evict each other: the voice starts with the first want, rising over its `fade`, plays at the largest of its wants' volumes each times the listener's gain at its wanter, the one heard loudest as 01's `nearest_gain` picks it (`examples/01_platformer/src/features/audio/systems.rs:93-100`), panned toward that wanter, and fades out with the last want. Wants live in a kit resource keyed by sound ID, then by wanter (an entity's cue loop, or a look's instance in Step 8), apart from the voice, unsaved (Q9, Q14). At each run's start, after the listener moves, each voice follows its loudest wanter: a command past a change of 1/64, and always a change to or from 0, so a voice past hearing reaches 0 (the hum's known issue, A19); a want whose subject is gone or despawning lets go, the last one's voice fading over 0.1 s. A voice the game's own plays evict, or the pool refuses, is not recovered, since the kit cannot see it (A19). With no want the pass returns at once (P7-13's kit loops).
- `SoundOnEvent::with_point(map)`: an event with a point plays by the World's `CueListener`, its gain (skipped at 0, the interval unmarked, as a cue sound's) and its pan; without a point or a listener, as today (ROADMAP.md's Later line on `SoundOnEvent`).

### 2.4 Named world cues (Step 4)

- The `world_cues` data kind: an entry is a list of `cue_action`s, its ID the cue's name.
- `WorldCue::new(name, at)`, `with_amount`, then `play(world)` queues it on `EventQueue<WorldCue>`, which the first play registers, so a World that plays none holds no queue. The cue system plays each after every other source, in send order, at its point with no subject: `prefab` and `roll` spawn there with no source, `sound` and `shake` by the listener (2.3), a `label` with a style floats the amount, `counter` and `flag` act with `target: game`. The load refuses the rest: `despawn`, `squash`, `flash`, `effect`, `ability`, `loop`, `stop`, a type label, and a counter or flag on a subject or other. An unknown name plays nothing and warns once; a world cue traces under `Entity::PLACEHOLDER` with today's kinds (A18; S-79, Q7).
- The kinds grow from 10 to 11: coverage, the census and the template's `AGENTS.md` (about 14 bytes, A15).

### 2.5 The hit flash's interval and the shield's take (Step 5)

- `HitFlash::with_min_interval(seconds)` (`"min_interval"`, 0 by default): a start within `seconds` of game time of the last one, a hit's or a `flash` cue's, leaves the flash as it runs, the time counted by the flash tick; so a beam's 0.1 s pulses flash once an interval and a tint shows between (K28).
- `HitFlash::with_shield(color)` (`"shield"`): a hit the `Shield` takes whole flashes `color`; unset, it flashes as any hit (K27).
- `Damaged::absorbed` (`with_absorbed`): what the shield took of `amount`, 0 without one. A `damaged` rule's `absorbed`: `true` passes a hit the shield took whole, `false` one that hurt (K27; `Occurrence`'s fifth bit). The window opens as today (Q1).

### 2.7 Status looks: tint, overlay and glow (Step 7)

- `Effect::with_look(Look)`, data `"look"`; a band's `look` replaces its effect's while that band is the highest its intensity holds (Q4). A look's share: a status's intensity over its max; another effect's stacks over its limit.
- `tint` (`[r, g, b, a]`, linear): the holder's drawn `Sprite.color` is the colour the frame's writers left it (a colour tween, the game) taken toward `tint` by the share times `a`; several multiply in instance order (Q3). The late pass keeps the colour it read and the one it wrote; the next frame's early pass puts the read one back only while the sprite still holds the written one, so a tween's or a game's write becomes the new base and the last look's end leaves the colour as the frame's writers left it.
- `overlay` (`{ "animation", "speed", "offset", "z", "material" }`): an entity drawing the clip, looped, at the holder's drawn centre plus `offset`, mirrored and turned with it, `z` above the holder's (1 by default), at `speed`, from a phase drawn from the holder's index so holders don't play in step, through `material` when set.
- `glow` (`{ "color", "radius" }`): `engine_white` through `engine_glow`, `radius` px about the drawn centre, one below the holder, its alpha by the share; a World without them skips it with one warning.
