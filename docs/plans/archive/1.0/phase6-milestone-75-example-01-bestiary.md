## 2. Design

### 2.1 Step 1's API (level C)

Additive; no break, no ledger row. Each saved form follows `D-197`'s pattern: settings and runtime state, checked like the scene form, with entity references left out for the game to name again by its own IDs (A6).

```rust
// intent/state_machine.rs
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(bound(serialize = "S: Serialize + Copy", deserialize = "S: Deserialize<'de> + Copy"),
        try_from = "MachineSave<S>", into = "MachineSave<S>")]
pub struct StateMachine<S> { /* unchanged fields */ }
impl<S: Copy + Eq + 'static> StateMachine<S> {
    /// The state a `go` asked for that the next visit enters; `None` when none waits.
    pub fn pending(&self) -> Option<S>;
    /// Holds or releases it: a held machine is not visited, so a pending `go` waits, no hook
    /// runs and its elapsed stands; a game holds a stunned, frozen or far-off entity's machine.
    pub fn set_held(&mut self, held: bool);
    /// Whether it is held.
    pub fn is_held(&self) -> bool;
}
// MachineSave<S> (private, deny_unknown_fields): state, previous, elapsed (finite, >= 0), next,
// entered, held. A loaded machine whose first visit ran runs no enter hook again; a pending `go`
// is entered at its first visit after the load, the old state's exit hook first, as the
// uninterrupted run would. The visit skips a held machine whole (`state_machine.rs:278`).

// overlap/hit.rs
impl Hitbox {
    /// The targets it has hit in this activation, in the order it hit them.
    pub fn hit_targets(&self) -> &[Entity];
    /// Replaces them: a loaded activation, given its targets by the game's IDs, hits none twice.
    pub fn set_hit_targets(&mut self, targets: impl IntoIterator<Item = Entity>);
}

// overlap/contact.rs
/// One target a contact damage touches: the seconds since it last hurt it and since they last met.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct ContactTouch { /* target, since_hit, since_met: private */ }
impl ContactTouch {
    /// Panics unless both seconds are finite and at least 0.
    pub fn new(target: Entity, since_hit: f32, since_met: f32) -> Self;
    pub fn target(&self) -> Entity;
    pub fn since_hit(&self) -> f32;
    pub fn since_met(&self) -> f32;
}
impl ContactDamage {
    /// Its targets, as `ContactTouch`es against its own clock.
    pub fn touches(&self) -> impl Iterator<Item = ContactTouch> + '_;
    /// Replaces them after a load: each target is next due `interval − since_hit` from now and
    /// forgotten an interval after it last met, as before the save.
    pub fn set_touches(&mut self, touches: impl IntoIterator<Item = ContactTouch>);
}

// motion/top_down.rs
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(try_from = "MoverSave", into = "MoverSave")]
pub struct TopDownMover { /* unchanged fields */ }
// MoverSave (private): speed, direction, acceleration, deceleration, velocity; the filter and the
// first-step flag left out, so a loaded mover takes its still first step as a loaded controller does.
// The runner keeps a not-started kinematic mover's kept velocity through that still step, as the
// controller returns before touching its own (A5), so a loaded mover resumes from it.
```

`ContactTouch` takes its root path in `lib.rs` beside `ContactDamage` (`lib.rs:274`). The hitbox's and the projectile's scene docs say a game names the targets again; `tests/hit.rs:202` and `contact_damage_is_data_without_its_timed_targets` keep their claims (the saved forms still leave entities out). Two system bodies change, each only for state that a hold or a load brings: the state machine's visit skips a held machine, and the top-down mover's still first step keeps its kept velocity. An unheld machine and a fresh mover, whose kept velocity is zero, behave as before, so the kit hash holds. No criterion row measures the state machine; the mover's one row, `top_down_mover_bodiless`, is captured before and after (step 1).

### 2.3 The enemies' frame

- **Files.** `features/enemies/mod.rs` holds `EnemiesPlugin`, the constants, the kinds' table (`EnemyKind`: prefab, box, mass, summon icon), `spawn`, `summon`, `difficulty` and `live`; `components.rs` holds `Enemy` (kind, home, heading), `Brain` (the last-seen point, a search point, the alert point, the hold), `Sight` (seconds to the next check, whether it sees, range), `EnemyState` (`Patrol`, `Alert`, `Chase`, `WindUp`, `Attack`, `Recover`, `Search`, `Return`; serde) and the save records' types; `systems.rs` holds the sight, alert, dormancy and death systems and the shared hooks; one file per kind holds its hooks and rules.
- **Order.** In `FixedUpdate`: `enemy_sight`, then `enemy_alerts`, then `enemy_hold`, then `enemy_states` in the intent phase, before the movers; every damage, heal and effect request an enemy makes is queued there, or in the overlap phase, so the step's own resolve takes it (`D-200`). `enemy_deaths` reads `Damaged` in the react phase (Death, below).
- **Holds.** `enemy_hold` holds an enemy's machine (`set_held`) while it is dead, dormant or carries `status.frozen` or `status.stunned`, and releases it otherwise, with its mover's input at rest while held. A dead enemy needs it: its despawn comes in the react phase of the step after the kill, after that step's visit, so a pending attack would start (`kit/damage/health.rs:880-905`, `kit/lifecycle/ended.rs:59-68`). The hold is recomputed each step from saved state, so a load holds the same machines. A held machine's pending `go` waits and its elapsed stands, so a wind-up's tell resumes after a thaw with the time it had left; a stun first replaces a wind-up with `Recover`, so it interrupts the attack before it lands (as (b)'s design says), while an attack already running finishes its hitbox window, which the kit counts down whatever the machine does (A1, A15).
- **Sight.** Every 0.2 s an awake enemy within its range casts from its eye to the player's centre: `cast_ray` over tiles (`with_bodies(false)`), then over bodies in layer 1 (`with_mask(1 << 1)`, tiles out), the nearer hit blocking. Step 3 gives the slabs' `rigid_body` `layers: [1]`; every other body stays in layer 0 with the default mask, so nothing collides differently. Seeing sets `last_seen`. The sight's clock and result are saved.
- **Alerts.** The first check that sees the player sends `Spotted` (the spotter, its point) and gives every awake enemy within 320 px that is not already chasing the alert point; it enters `Alert` at its next visit. `CuesOnEvent<Spotted>` turns the event into the cue `spotted`, whose rule plays the alert sting. The alert point is saved.
- **Dormancy.** An enemy more than 1,200 px from the player thinks nothing: no sight check, its machine held. It is recomputed each step from saved positions, so a load wakes the same enemies (Q7).
- **States.** `Patrol` moves by kind near home; `Alert` plays the kind's tell for its seconds, then `Chase`; `Chase` closes in while it sees, enters `WindUp` in attack range and `Search` when sight is lost; `WindUp` is the attack's tell (signalled before it lands); `Attack` runs the kind's attack; `Recover` ends it; `Search` goes to `last_seen` and looks for 3 s; `Return` goes home, then `Patrol`.
- **Difficulty.** At spawn, map-placed, summoned or loaded, an enemy's `max_health` and `damage` take `Mul` 0.75, 1 or 1.5 from the source `difficulty`, read from the run's `RunMeta`; a load's restored `Stats` already carry it, so a load never adds it twice. Ailment thresholds, the player and the dummy are not scaled. The New Game note reads `150 health · enemies ×0.75` (Q11). 01's own damage from an enemy (the slam, a thrown body) scales by that enemy's `damage` stat over its base.
- **Hurting each other.** Attack hitboxes carry no filter, so they hurt every hurtbox but their own; the slam and thrown bodies hurt every `Health` entity but the thrower; explosions and steam already do (A25). Touches are filtered to `team.player`, since a touch is not an attack.
- **Death.** `despawn_on_death` 0, so a dead enemy goes the step after the kill. Hit items act until the despawn marks their entity, which comes after that step's overlap phase (A14), so `enemy_deaths` takes a killed enemy's `ContactDamage` and `Hitbox` off in the react phase of the killing step; its burst by state as the dummy's; a map-placed enemy's save ID joins `gone`, so a Retry or a Load keeps it dead; a troll that dies, freezes, is stunned or leaves drops what it holds (§2.4).
- **Frozen enemies.** The kit's `frozen` effect only grants `status.frozen`, so the hold above stops the AI. A walker keeps its controller with its input at rest, so it falls, takes `push` from the black hole and blasts and `launch` from a throw; a flyer swaps its `TopDownMover` for a `PlatformerController` with no input and gets the mover back at the thaw. Both drivers are saved.
- **The black hole.** It pushes walkers and flyers through their movers (`push`, `knock_back`) at a response per kind and slows the troll with a `move_speed` modifier from the source `black_hole` while it is inside its reach, removed when it is not (A23).
- **Summons.** `SUMMONS` takes each enemy after the dummy as its kind lands; `fits` takes the type's box; at most six summoned enemies live, the oldest going with a poof, beside the dummies' four.
- **Placements.** The map's new last object layer, `enemies`, after `dummies`: two wisps (the tower's upper hall), two crawlers (the aqueduct's upper ledges past column 44), two beetles (the tower's floor), two bats (under `switch_a`–`c`) and the troll (the pit's floor), nine in all, none within 1,300 px of the clearing, so the clearing's tests never wake one (Q3). `save::MAP_ENEMIES` counts them.
