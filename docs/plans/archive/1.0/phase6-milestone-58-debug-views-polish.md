## Context digest

M57 (0.77, `D-165`, `D-166`) moved the HUD, the systems overlay, the entity inspector, the log console (F8) and the UI inspector (F7) onto the core UI as movable windows on `UiLayer::Debug`, every node overriding every style. Its sizes came from the old text overlays (26–32 units), and its windows scale with `ScaleFactor::get()`, the OS scale times the player's UI scale. On the owner's display (Xft.dpi 168, OS scale 1.75) a 1280×720 window holds 731×411 units, so 28-unit text draws about 49 px tall and the five windows cover one another: known issues' M57 row, which this pass closes. The plan session's captures of the `debug` fixture at 1280×720, 1920×1080 and 2560×1440 (0.77, OS scale 1.75) show the overlap, rows cut at the window edge, the HUD's zeros at frame 60 and the see-through fills.

The owner settled the fix the same day (§2.1). This plan adds no candidate: its register row and roadmap stop sit before W6b and W6c. It stands on M56's paint-only transforms (`D-163`), M57's mesh command, scroll panels, drag handles and placements file (`D-165`, `D-166`), the engine font (`D-123`) and the engine logger's `Tee` (`D-119`, `D-165`).

Core gains a scale of its own for the debug layers, raising a window root on press, node shadows drawn as meshes, a line limit in the headless measure double and a zoom in the placements file (decision 167). The umbrella's views take the rest: units, caps, docked places, the palette, the SemiBold face, chrome and the new columns (decision 168). W12b with W1 M6 moves the examples onto the UI views next and inherits these defaults.

## 2. Design

### 2.1 What the owner settled (2026-10-15)

- **Sizing.** Body text about 15 UI units, titles one step up. The debug layer on the OS scale only, not the player's UI scale. Each window capped near 45% of the viewport's width and 60% of its height, its body scrolling. The views step down on small windows. Zoom keys (Ctrl+=, Ctrl+-, Ctrl+0) saved with the window places. Long rows truncated with an ellipsis, and the HUD's `ui` row split. Default places that do not overlap at 1280×720: HUD top-left, systems top-right, inspector bottom-left, UI inspector bottom-right, log a bottom strip.
- **Font.** JetBrains Mono stays; its Bold or SemiBold is embedded as `engine_mono`'s bold face for titles, headers and key numbers, with its notices line.
- **Look.** Dark mode, with vibrant colour as an information channel. Surfaces and chrome stay neutral: near-black, near-opaque panels; a slightly lighter title bar with a bold title and its toggle key dimmed at the right; a 1 px border and a soft shadow; grey labels and off-white values; section headers and faintly striped table rows; hover and drag brighten the border. Saturated colour appears only where it carries meaning, from one shared palette, each hue's meaning fixed within a view: a budget ramp from green through yellow and orange to red for frame times, graph bars and system timings; a hue per log level on its badge (ERROR red, WARN amber, INFO cyan, DEBUG violet, TRACE grey), ERROR and WARN messages tinted to match; a hue per value type in the inspector (numbers, strings, booleans, entity references); a hue per schedule stage for the systems overlay's groups. Colour is never the only cue (the number or label stays beside it), and every text colour keeps at least 4.5:1 contrast against its panel.
- **HUD.** The frame graph takes a fixed width, with lines at 16.7 and 33.3 ms and min, average, max and 1% low beside it; the HUD shows a dash, not zeros, before its first refresh.
- **Tables.** The systems overlay gains max and share-of-frame columns, inline bars, stage groups and the total in its title; the inspector one header per component with its fields indented; the log console time, level, short target and message columns, level filters, pause and clear.
- **Window chrome.** Close and collapse buttons, raise on click (its backlog row), snap to edges.
- **Not in this pass:** the UI inspector's on-screen outline, breadcrumbs and swatches, and a debug menu: they become backlog rows.

### 2.2 Core: the debug layers' own scale (decision 167)

- **`UiTree::set_debug_scale(&mut self, scale: f32)`** and `debug_scale(&self) -> f32`: how many of the tree's UI units one unit of a `Debug` or `DebugPopup` root spans; 1 on a new tree. Kept as given, not rounded, so 2.3's factor cancels any player scale exactly; a value that is not finite or not positive is ignored; a change marks the debug roots for layout and the tree for paint, and an equal value marks nothing.
- **Layout.** A debug root lays out in the viewport divided by the debug scale. `UiTree::layer_viewport(&self, layer: UiLayer) -> Option<Vec2>` returns the viewport the last layout gave that layer's roots, in their units; `None` before the first layout. The text scale (`set_text_scale`, M56) applies to `Game` and `GamePopup` roots only: debug labels and controls skip it, in `prepare_text` and in the control measure (`taffy.rs:390`).
- **Paint, hit testing and `visual_rect`.** A debug root's map starts at a scale of the debug scale about the viewport's origin, composed with M56's node maps, so its boxes, borders, radii, meshes, clips and text land at the physical scale times the debug scale; its translations and scroll offsets round to whole physical pixels at that product. A text run under it draws at the debug scale exactly, times M56's node scales stepped to 32nds as before (`paint.rs:120-130`): the layer's scale never steps, so the run fills its box with no shrink. `PaintList::scale` stays the tree's. A debug root's `rect` is in debug units and its `visual_rect` in tree units.
- **Windows.** `set_window_position` clamps a root inside its layer's viewport.
- **Routing.** A drag moves a debug root by the pointer's motion divided by the debug scale; a pixel wheel delta over a debug scroll panel is divided by it too, and a line delta stays `scroll_line` units of the panel. Directional focus compares layout rects, which are debug units on a debug root, so moving focus between a game root and a debug root is approximate; no debug view takes focus.
- **Raise.** `UiTree::raise(&mut self, root: WidgetId) -> bool` moves a root after the other roots of its layer, so it paints over them and is hit first; it marks paint and returns whether the order changed, `false` for a widget that is not a root. The router raises the root under a primary press the UI takes when that root's role is `Role::Window` and it is not frozen, before handling the press, so the raised window also takes the press. Only the debug views use `Role::Window` today (`debug_views.rs:267`).
- **Shadows.** `UiShadow` in `ui::node` (`#[non_exhaustive]`; `color: [u8; 4]`, `blur: f32`, `offset: Vec2`; `UiShadow::new`), `UiTree::set_shadow(&mut self, id, Option<UiShadow>)` (marks paint; an equal value marks nothing) and `shadow(&self, id) -> Option<UiShadow>`. A node with a shadow paints, before its box, one `PaintCommand::Mesh`: its box moved by `offset` and filled with the colour, and a ring `blur` wide around that fading to transparent: nine quads, 54 vertices; the alpha times the node's, under the node's map and in its inherited clip. Nothing when `blur` is not finite and positive or the colour's alpha is 0. Render is unchanged: the mesh pipeline draws it (`D-165`), and the shader's reserved fields stay reserved. Hit testing ignores shadows.
- **Measure double.** `FixedAdvanceMeasure` caps a definite-width measurement at `n` lines under `TextOverflow::Ellipsis { lines: Some(n) }` (`n` of 0 keeps one line), as the engine does (A18); `lines: None` keeps every line, as the engine's measurement does.
- **Placements' zoom.** `WindowPlacements::zoom(&self) -> Option<f32>` and `set_zoom(&mut self, zoom: f32) -> bool` (`false`, keeping nothing, unless finite and positive). The file gains an optional `"zoom"` number beside `"windows"` and stays version 1, since a 0.77 build ignores the key (A16). A zoom that is not a finite positive number loads as none with one warning, as a bad entry does; `save` writes it when set. Positions mean what their caller stores; the umbrella's units are 2.3's.

### 2.3 The views' scale, step, zoom and places (decision 168)

- **The factor.** Every frame, before its early return, `debug_views` sets the tree's debug scale to `zoom × step / ScaleFactor::ui_scale()`, so the debug layers draw at OS scale × zoom × step whatever the player's UI and text scales.
- **Step.** From the OS-logical viewport (`WindowSize` divided by `ScaleFactor::os()`): the largest of 1, 7/8 and 3/4 at which that viewport divided by the step holds 960×540 units, else 3/4. At OS scale 1.75, a 1280×720 window steps to 3/4 (a 975.2×548.6-unit debug viewport) and 1920×1080 and 2560×1440 stay at 1; at 1.0, 1280×720 stays at 1 and 800×600 steps to 3/4.
- **Zoom.** 1 by default, 1/2 to 2 in eighths. Ctrl+= (Shift allowed) one eighth up, Ctrl+- one down, Ctrl+0 back to 1, each press counted, OS repeats included, read from the frame's raw key events while any view is shown; nothing reads them while every view is off. A change goes through `WindowPlacements::set_zoom` and `save` at once; a failed save warns once per run, as places do. The keys still reach the game.
- **Places.** Saved in OS-logical units (physical pixels divided by the OS scale): a debug-unit place times `ui_scale × debug_scale`. A saved window is placed from its logical place whenever the debug scale changes, so a zoom keeps its top-left where it was on screen. A 0.77 file's places, written in UI units at `ui_scale` 1, read the same.

### 2.4 Look and palette (decision 168)

- **Sizes.** Body 15 units on 20 (each view's `font_size` and `line_height` defaults). Titles two units more (17 on 22) at weight 600; headers and key numbers at weight 600. Inset 6 units; table cells padded 6 a side with no column gap, so stripes run unbroken; indented cells 12 more. `padding_px` (the margin) 8. `outline_px` becomes physical pixels again, as its name says: 1 by default, `outline_px / (ScaleFactor::get() × debug_scale)` units on the node. Corner radius 4.
- **Font.** `engine_mono` gains JetBrains Mono SemiBold (weight 600) as its second face, ID `engine_mono_semibold`: `crates/tungsten/assets/fonts/JetBrainsMono-SemiBold.ttf`, a copy of `assets/fonts/JetBrainsMono/static/JetBrainsMono-SemiBold.ttf`, compiled in and registered beside the Regular face; text at weight 600 picks it (A17). A manifest face under `engine_mono` still replaces the Regular face alone (`D-123`), and `docs/assets.md` reserves the new ID the same way. `EMBEDDED_WORKS` names both faces over the same OFL text: `JetBrains Mono Regular and SemiBold, the engine font (tungsten, D-123)`.
- **Palette**, crate-private constants in `debug_views.rs`, one table every view reads; the starting values below pass the contrast rule:

- **Rules.** Chrome stays neutral. No view uses one hue for two meanings: the systems overlay's stage hues avoid the ramp's four. The values above give 4.99:1 at worst (RED on the title bar over white); in linear light a small veil lifts near-black a long way, which is why the veils are 5 and 2 and the panel is 252: at 248 the same case falls to 4.24:1, and at M57's 245 to 3.81:1. A button's hover turns its glyph from `LABEL` to `VALUE` and changes no fill, so contrast holds.

### 2.5 Windows (decision 168)

- **Structure** as M57's, with one addition: a root on `UiLayer::Debug` with `Role::Window` and its title as accessible name, holding the title bar (`children[0]`), then, for a view that has one, a fixed header that never scrolls (the HUD's graph block, the console's controls line, the inspectors' header lines), then the body, a scroll panel holding the table alone (the last child). The fixture finds the body as the root's scroll-panel child, so its lookup stays. The root takes the view's `background`, the 1 px border in `outline_color` (`BORDER_HOT` while the pointer is over the window, by the hit test's root under the cursor, or its title bar is pressed) and the shadow.
- **Title bar**, a drag handle row on the title veil: the title (weight 600, `Fill`, ellipsis); the view's toggle key, the first binding of its action by `Binding::label` (`F4` for the HUD), in `LABEL`, none when unbound; a collapse button (`–`, `+` while collapsed); a close button (`×`). Buttons are interactive and not focusable, every override set on the button and its label (A19).
- **Close** sets the view's `enabled` to false, as its key does. **Collapse** sets the body `Collapsed` and back; it is not saved, as open state is not (`D-166`). Both act on `UiEvent::Activated`.
- **Raise** is the router's (2.2): a primary press anywhere on a window brings it forward.
- **Snap.** Each frame, a saved window whose edge lies within 16 units of the margin line (`padding_px` in from a viewport edge) moves onto it, per axis; a drag's end saves the snapped place.

### 2.6 Caps and docked places (decision 168)

- **Caps.** A corner window is at most 45% of the debug viewport's width and 60% of its height; its body scrolls past that. The log console docks as a strip along its corner's horizontal edge, `BottomLeft` by default (the bottom): the viewport's width less twice its margin, and at most 25% of the height.
- **Defaults.** HUD `TopLeft`, systems `TopRight`, inspector `BottomLeft`, UI inspector `BottomRight`, log console `BottomLeft` as a strip.
- **Docking.** A window with no saved place docks (M57's rule). Before each layout, the views give every docked window a fixed height (`Sizing::Px`) and place it; layout never grows it past that, and content that does not fit scrolls in its body. A window's wanted height is what its content asked for at the last layout: its body's bottom plus the body's `scroll_max`, plus the root's bottom padding and border, less the root's top (its cap before its first layout; its title bar's height while collapsed). The strip takes min(wanted, 0.25 H) and pushes its edge's corner windows away by that plus its margin. A side (the left corners, or the right) has the space C = H − 2m − (each docked strip's height + m). Windows docked on a side stack from the top corner down and from the bottom corner up, in the views' update order (HUD, systems, inspector, log, UI inspector), each taking min(wanted, 0.6 H, C − the heights given earlier on that side, each with its margin, − (6 lines + m) for each window still to place there). So a top window leaves its side's bottom window at least six lines, and the bottom one takes the rest; alone on a side, a window takes up to 0.6 H. A window that grew this frame scrolls for one frame and takes its new height at the next.
- **Guarantee.** At a debug viewport of at least 960×540 units, which 2.3's step keeps down to 3/4, the docked windows never overlap on any frame, since their heights are set before the layout that lays them out: pinned at 1280×720 at OS scales 1.0 and 1.75, frame by frame through a collapse, an expansion and a growing row.

### 2.7 Tables (decision 168)

- **Columns** stay column-major and sized by layout (`D-165`). Every text cell wraps by glyph with `TextOverflow::Ellipsis { at: End, lines: Some(1) }`, so a long cell ends in `…`. Each table has one `Fill` column (a value, name or message) that takes the width the others leave inside the window's cap; the other columns are `Auto`, never shrinking (`taffy.rs:128`), so each `Auto` column holding free text carries a `max_width`: 40% of its window's width cap for a label or field-name column (the HUD's labels, the inspectors' names), 20% of the strip for the console's target column. Short fixed columns (numbers, the time, the level) need no cap. The title, header lines and the console's counts truncate the same way.
- **The probe.** A headless test holds long cells to the cap: a 200-character custom HUD row (label and value) leaves the root at 45% of the viewport, its label column at 40% of that, and both cells one line tall; a long console target stops at 20% of the strip. If Taffy's flexbox sizing does not hold the `Fill` column that way, the fallback is an `Auto` column with a `max_width` of the cap less the other columns' widths from the last layout; the run records which it took, and it is not a stop.
- **Rows.** Data rows alternate a faint stripe (`STRIPE_VEIL` on each cell of the row); header rows are weight 600 and unstriped; cells under a header indent by 12 units. A bar cell (the systems overlay) is a 48-unit track holding a fill of its fraction's width, 6 units tall and centred. A missing value reads `–`.

### 2.8 The HUD (decision 168)

- **Header and body:** the graph block in the fixed header, always in view; the rows in the body (labels `LABEL`, values `VALUE`).
- **Graph block:** the mesh at a fixed 240 × (4 × line height) units, one unit per interval, the newest at the right, on the stripe veil; bars in the ramp's colours; guide lines at 16.7 and 33.3 ms, one unit thick, `LABEL` at half alpha, over the bars; scaled against the larger of 33.3 ms and the tallest bar (`D-165`). Beside it four rows: `min`, `avg`, `max` and `1% low` (the mean of the slowest 1% of the shown intervals, at least one), each in ms at weight 600 in the ramp's colour.
- **Ramp** (frame times, bars, the fps row's ms): up to 16.7 ms green, 25 yellow, 33.3 orange, above that red: bands at 1, 1.5 and 2 times the 60 Hz budget.
- **Rows:** `fps` (`1000 / average interval`, and the average CPU frame time at weight 600 in the ramp's colour); the built-in providers; the game's (`DebugHud::add_row`, unchanged). The `ui` row splits into `ui` (commands, layout µs, roots and nodes laid out), `text` (batches, prepared, full frames, atlas full, layouts) and `labels` (world labels kept, culled and dropped, glyphs).
- **Before data:** both averages start from the first interval, not 0; until it arrives, the fps, cpu and four stats values read `–`; the first refresh after it runs at once, then every `refresh_interval_ms`.

### 2.9 The systems overlay (decision 168)

- **Title** `Systems · <total> ms`, the sum of the averages.
- **Columns:** name (`Fill`, ellipsis), avg ms, max ms, % of frame, bar; a column-header row (`LABEL`, weight 600).
- **Groups:** one per stage in frame order (Startup while present, PreUpdate, FixedUpdate, Update, PostUpdate, then `other` for a name the schedule does not list). A header row carries the stage's name in its hue at weight 600 and its total; its systems follow, slowest first, indented.
- **Stage map:** `App::resolve_schedule` inserts a crate-private `SystemStages` resource (each name's stage, from `Schedule::names`), beside `UiRouteInstalled`; without it every system is `other`.
- **Numbers:** avg is the EWMA (`alpha` 0.1, as now); max is the largest single-frame time over the last four refreshes (2 s at 500 ms); % of frame is avg divided by an EWMA of `FrameTimings::total_ms`; the bar shows that share. Avg, max and the bar take the ramp against a 1.67 ms system budget (a tenth of a 60 Hz frame: bands at 1.67, 2.5 and 3.33 ms).

### 2.10 The inspectors (decision 168)

- **Entity inspector:** a header line in the fixed header, `entity Entity(n)` at weight 600, or `middle-click an entity to pick`. Two columns: one header row per component (its name at weight 600), then its fields, indented, names in `LABEL` and values in their kind's hue: `true` and `false` violet, a number or a bracketed or parenthesised list of numbers cyan, `Entity(n)` amber, anything else green. `(no registered components)` when none.
- **UI inspector:** M57's rows in the new look (names `LABEL`, values `VALUE`, the header line in the fixed header at weight 600). The outline, breadcrumbs and swatches stay out (§2.1).

### 2.11 The log console (decision 168)

- **Drain:** raw records into the ring; nothing parses or colours them there, so a hidden console costs less than M57's (A13, A22).
- **Parse at row build:** `logging::record_fields` reads `env_logger`'s default format, pinned by a test through `logging::builder`'s own output: time `HH:MM:SS`, level, short target (the last `::` segment), message (its first line, then ` …` when more follow). A record that does not parse shows whole as its message, with no level, and every filter passes it.
- **Columns:** time (`LABEL`), level badge (the level's name at weight 600 in its hue on the badge fill), target (`LABEL`), message (`Fill`, ellipsis; `VALUE`, or `ERROR_TEXT` and `WARN_TEXT`).
- **Controls line,** in the fixed header, so it stays in view and takes clicks while the body follows the log's end: five level filters (`[x] ERROR` in its hue while shown, `[ ] ERROR` in `LABEL` while hidden), `pause` (`resume` while paused), `clear`, then `N lines · D dropped`, `paused · N new` while paused, or `no engine logger`.
- **Behaviour:** pause stops the window taking lines while the ring keeps draining; clear empties the ring and the window (`LogConsole::clear`, public); a filter change rebuilds the rows; the body follows its end until the wheel moves it off (M57).
