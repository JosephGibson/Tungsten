## Context digest

W1's ladder is the longest chain to 1.0 (M0a → M1 → glyph gate → M2 …, implementation plan §6), and M0a heads it. The definition gate moved the render thread (R4) to 1.x (Q4, `D-102`), so the text engine can stay on the main thread in `tungsten-render`, beside glyphon, and M0a runs in Track A. W1 M1's `UiTree` needs a measurement interface whose min- and max-content results match what the renderer later draws (w01 §4); today shaping is private to `TextPipeline` and every font load clears every layout.

It stands on `D-026` (glyphon and cosmic-text), `D-085` (the bounded section cache, whose behaviour stays), `D-007`/`D-016`/`D-018` (core defines neutral types and never calls render; render mints handles, as `D-048` has it), `D-009`/`D-017`/`D-089` (manifest IDs, merge and cross-references on the merged graph) and `D-015` (no new dependency: glyphon re-exports `cosmic_text`, which holds `Fallback`, `Ellipsize`, `Hinting` and `FontFeatures`).

Later candidates expect from it: M1 calls `TextMeasure` from core through an engine the umbrella lends; M2 draws nodes from the same retained buffers and carries `FontEpoch` in its paint list; the glyph gate scores the DPI and hinting fork on the hinting switch this plan exposes; W12a embeds the HUD font into the packaged-only database; localization later adds locale to font selection, which bumps the epoch.

## 2. Design

Level B: approving this plan approves the API sketch below. Names are binding unless an open question changes them.

**Core, `tungsten_core::text` (new; no glyphon, no wgpu).** Neutral types the engine, M1's layout and M2's paint list share:

```rust
pub enum TextAlign { #[default] Start, Center, End, Justified }  // logical; Start = cosmic `None`
pub enum TextWrap { None, Glyph, Word, #[default] WordOrGlyph }    // cosmic-text's own default
pub enum EllipsisAt { Start, Middle, End }
pub enum TextOverflow { #[default] Clip, Ellipsis { at: EllipsisAt, lines: Option<u32> } } // per paragraph (Q10); None: the committed or bounds height
pub enum TextHinting { #[default] Disabled, Enabled }
pub struct FontFeature { pub tag: [u8; 4], pub value: u16 }
pub struct FontFeatures(Vec<FontFeature>);                         // FontFeatures::tabular_figures()
pub struct TextLayout {                                            // Default reproduces A5 exactly
    pub align: TextAlign, pub wrap: TextWrap, pub overflow: TextOverflow,
    pub hinting: TextHinting, pub letter_spacing: f32, pub features: FontFeatures, // letter_spacing in em
}
pub struct TextStyle {
    pub family: String, pub weight: u16, pub italic: bool,         // a `font_families` ID (step 3)
    pub size: f32, pub line_height: f32, pub color: [u8; 4], pub layout: TextLayout,
}
pub struct TextSpan { pub text: String, pub weight: Option<u16>, pub italic: Option<bool>, pub color: Option<[u8; 4]> }
pub struct StyledText { pub spans: Vec<TextSpan> }                 // From<&str>: one span
pub enum MeasureWidth { MinContent, MaxContent, Definite(f32) }    // Taffy's AvailableSpace
pub struct TextMetrics { pub size: Vec2, pub first_baseline: f32, pub line_count: u32 }
pub struct TextNodeId { /* index, generation; minted by the engine */ }
pub struct FontEpoch(/* u64 */);
pub trait TextMeasure {
    /// `known_width` is a width layout has already fixed; it wins over `available`.
    fn measure(&mut self, node: TextNodeId, known_width: Option<f32>, available: MeasureWidth) -> TextMetrics;
}
```

Every new public enum, and every new struct that may grow (`TextLayout`, `TextStyle`, `TextSpan`, `TextMetrics`, and step 3's `ResolvedFontFamily`), is `#[non_exhaustive]`, as the ledger asks of new types (A21); those structs get `Default` or `new` and `with_*` setters, since a crate outside cannot build them by literal.

**Width modes.** Min- and max-content ignore overflow (as CSS does) and are cached on the node per text, style and epoch. Max-content is the unwrapped width in every mode. Min-content is the widest word for `Word` and `WordOrGlyph`, the widest glyph for `Glyph` and the unwrapped width for `None`; the engine gets it from a relayout at width 0 under `Word` (for both word modes: under `WordOrGlyph` width 0 would split every word into glyphs) or `Glyph`. A definite width relayouts the retained buffer with the node's overflow; probes never reshape (A10). `measure` has no height input, so it lays out with unbounded height: `Ellipsis { lines: Some(n) }` applies there, while `lines: None` takes its height only at `commit_layout` (from the committed size) and in a section (from its bounds), so the same measure call always returns the same result. cosmic-text applies an ellipsis limit to each paragraph separately (`shape.rs:2327-2340`, called per line from `buffer.rs:701-716`), so `lines` counts lines per paragraph (Q10). An empty text measures one line height. A stale or removed `TextNodeId` measures `TextMetrics::default()` and logs once per ID, in every build; it does not assert.

**Render, `tungsten_render::text`.** `text.rs` stays the module root (A20): `TextSection` and the re-exports. `text/engine.rs` holds `TextEngine`, the device-free half: the font system, faces, families, the chain, the epoch, the `D-085` section cache and the nodes. `text/fonts.rs` holds font sources, family resolution and the `Fallback` implementation; `text/nodes.rs` the retained nodes; `text/gpu.rs` `TextPipeline`, which owns the engine and the glyphon atlas, renderer, viewport and swash cache, and keeps its public methods.

```rust
pub enum FontSource { Packaged, PackagedThenSystem }               // from RenderConfig::system_fonts
impl TextEngine {
    pub fn new(source: FontSource) -> Self;
    pub fn font_epoch(&self) -> FontEpoch;                         // bumps on font load, reload, families or chain
    pub fn create_node(&mut self) -> TextNodeId;
    pub fn remove_node(&mut self, node: TextNodeId);               // its buffer joins D-085's spare list
    pub fn set_text(&mut self, node: TextNodeId, text: &StyledText, style: &TextStyle); // equal input: no work
    pub fn commit_layout(&mut self, node: TextNodeId, size: Vec2) -> TextMetrics;      // the final width
    pub fn committed(&self, node: TextNodeId) -> Option<TextMetrics>;
}
impl TextMeasure for TextEngine { /* … */ }
pub struct TextNodes<'a> { /* &'a mut TextEngine, private */ } // node methods and TextMeasure, forwarded
impl Renderer {
    pub fn text_engine(&self) -> &TextEngine;
    pub fn text_nodes(&mut self) -> TextNodes<'_>;                 // M1 lends it to layout as &mut dyn TextMeasure
    pub fn set_font_families(&mut self, families: &HashMap<String, ResolvedFontFamily>, fallback: &[String]);
}
pub struct TextSection { /* the seven fields */, pub layout: TextLayout } // + Default (Q1)
```

`TextPipeline::new` keeps its signature (packaged fonts); `TextPipeline::with_font_source` takes the source. `Renderer::load_font` and `reload_font` keep theirs. No public function returns `&mut TextEngine`: the GPU half's atlas and swash cache key glyphs by the engine's fontdb IDs (A22), so swapping the engine under them (`std::mem::replace`) could reuse stale glyph images. `TextNodes` gives layout the node methods and nothing else; `TextEngine::new` stays public for GPU-free use.

**Fonts.** `FontSource::Packaged` builds an empty `fontdb::Database`, locale `en-US` (script fallback lists are empty, so the locale selects nothing), and a `Fallback` whose common list is the chain's fontdb family names and whose script and forbidden lists are empty. `PackagedThenSystem` starts from `FontSystem::new().into_locale_and_db()` for the system faces and locale (A9), adds the packaged faces, and appends `PlatformFallback`'s lists after the chain. A packaged face replaces any system face with the same fontdb family, weight and style (the engine removes the system face when the packaged one loads), since fontdb would otherwise pick whichever loaded first (A22). Family names reach the `Fallback` as `&'static str` through an interner the engine owns, which leaks each distinct name once (bounded by the faces ever registered; no global state). A chain change rebuilds the font system from its database. The chain sets the order of preference only: cosmic-text's last stage still tries every face in the database in `FontMatchKey` order (A8), so a glyph outside the chain's families is found in any packaged face that has it. Its last ordering field is the fontdb ID, so faces load into an empty database in sorted ID order, which makes a fresh start repeatable. A hot reload that adds or replaces a face appends it, so ties between faces of equal weight, stretch and style may resolve differently until the next start; visual tests and replays start fresh. Rebuilding the database in canonical order would close that gap, but it restarts fontdb IDs, which the atlas and the swash cache key glyphs by (A22), so this plan does not do it; `D-116` records the limit. A family resolves a style to one of its faces: an exact weight, else the nearest, ties to the heavier; italic exact, else upright, logged once per family and style. The engine warns when two registered faces share a fontdb family, weight and style, since `Attrs` then cannot tell them apart. An unknown family in a `TextStyle` resolves to the chain's head and logs once per ID; a section's unknown face ID keeps today's behaviour, now landing on the chain's head (Q3).

**Manifest (step 3).** A `font_families` section maps a family ID to the face IDs it groups, and a top-level `font_fallback` list names family IDs in order:

```json
"font_families": { "sans": { "faces": ["sans", "sans_bold"] }, "mono": { "faces": ["mono"] } },
"font_fallback": ["sans", "mono"]
```

Family IDs are their own namespace, as every section's are in `merge_entries` today (Q4). Cross-references are checked on the merged graph (`D-089`): each face names a `fonts` entry, each chain entry names a family. Chains concatenate in root order (`D-035`), keeping each family's first position.

**Seam.** Core gains types and a trait, never a render call (`D-007`); render mints `TextNodeId` (`D-048`'s pattern); extract still passes `TextSection` (`D-018`). The frame is serial, so M1's layout borrows the engine mutably after systems and before extract, and draw borrows it shared (w01 §4). There is no template yet (W12a).
