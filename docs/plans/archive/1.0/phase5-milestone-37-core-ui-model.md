Resolution, cached per node behind `(ThemeEpoch, the node's WidgetState, the node's override version, the parent's resolved text)`: non-text properties are the kind's `normal` visual, then the state variant's overrides, then the node's own; they never inherit. Text properties start from the theme's base (`fonts.body`, `text.size`, `text.line_height`, `colors.text`, weight 400) and pass down the tree: each ancestor applies its kind's text overrides and its own, in order, so a label inside a button takes the button's text colour and weight, and a node's own text overrides apply last. No selectors, no other inheritance (w01 §14). Resolution runs inside `layout()`: a change of theme, overrides, parent text or state (`set_enabled`, focus gained or lost) marks the node style-dirty and its root with it, `layout()` re-resolves style-dirty nodes on every root, and when a resolved text style changed in any property, colour included, the node is re-set and it and its root become layout-dirty, since the engine's `set_text` drops a node's shaping and committed layout on any unequal style (`crates/tungsten-render/src/text/nodes.rs:151-165`, `:59-66`) and the same `layout()` pass must restore the commit; a change of background, border or radius alone is paint-dirty. So a clean tree re-resolves and, when needed, relayouts after a focus or enabled change, since the `focused` and `disabled` variants may carry text overrides (Q10). `resolved_style(id)` returns the last result.

Layout (`layout.rs`, `layout/taffy.rs`): one Taffy tree per dirty root, built afresh for the pass (a root is small and the engine caches shaping per node, so no incremental mirroring and no `mark_dirty`), so a dirty root relayouts alone and a clean one costs nothing; a synthetic viewport-sized parent with the default `LayoutStyle` (a column, `Stretch`, `Start`) holds the root, so a root's `Auto` width stretches to the viewport, its `Auto` height is its content, and anchored roots and popups position against the viewport. `LayoutStyle` converts to `taffy::Style` by this table, which the spike's `flow()` encodes (`perf-runs/20261005-taffy-layout-spike/src/main.rs`):

| `Sizing` | Main axis (the parent's `direction`) | Cross axis |
| --- | --- | --- |
| `Auto` | content-sized, never shrinks: `size: auto`, `flex_basis: auto`, grow 0, shrink 0 | `size: auto`; follows the parent's `align_items` (`Stretch` by default, so a one-line label in a 60-tall row is 60 tall with its text at the top; `Align::Start` keeps content height) |
| `Fill` | the remaining space, shared: `flex_basis: 0`, grow 1, shrink 1 | `size: auto`, `align_self: Stretch` |
| `Px(v)` / `Percent(p)` | fixed: `size: length(v)` / `percent(p / 100)`, grow 0, shrink 0 | fixed size |

So a label wraps only when it fills or when the cross axis stretches it. `min_*`/`max_*` map to `min_size`/`max_size`; `padding`, `margin`, `gap`, `direction`, `align_items`, `justify_content` and `align_self` map one to one (`Edges` start/end to left/right). `Placement::Flow` is a relative flex item; `Anchored` is `position: Absolute` with `inset` of `offset` on each `Start` or `End` edge of the anchor and `auto` on the others (case D), and a centred axis gets inset 0 plus a post-solve shift of half the free space plus `offset` when the pass accumulates rects, since Taffy places an absolute child with auto insets by the container's `justify_content` and the child's `align_self`, not per node. `Collapsed` is `Display::None`; `Hidden` leaves the solver's style unchanged. Text nodes are leaves whose measure closure maps `known_dimensions.width` and the width's `AvailableSpace` onto `TextNodeStore::measure`, and rounding stays off (`disable_rounding`): boxes are fractional, the rounding rule is defined once at extraction (w01 §6, M2), and a rounded width could wrap a line that fit the measured one (case G). Taffy's per-node cache answers a second solve with no tree change without calling the closure (case E), so a clean root costs no measurement. After the solve, each root's boxes accumulate into viewport-space `Rect`s and every text node gets `commit_layout` with its solved box once (w01 §4's rule 1); a debug assertion checks that the commit's `line_count × line_height` equals the solved height within an epsilon, so measurement, the committed width and the computed height agree by construction. Text nodes are created and set at `layout()` for labels without one, re-set when the text or the resolved text style changed, and released at the next `layout()` after `remove`. `layout()` reads `text.font_epoch()` first: when it differs from the epoch of the last pass, every root that holds a text node becomes layout-dirty, so a font load or reload relayouts a clean tree without any tree mutation; the engine already rejects a commit made under an older epoch (`crates/tungsten-render/src/text/nodes.rs:197-201`). Hidden nodes are measured and laid out as visible ones are, since they keep their boxes; they only skip paint and hit testing. Only collapsed subtrees skip measurement, and a collapsed node has no rect.

Hit testing (`hit.rs`): roots from the highest layer down and, within a layer, the latest root first; children latest first, so the later sibling is in front; a node counts when visible, hit-testable, enabled or not (disabled nodes still block what is behind them), the point is inside its rect and inside every ancestor's rect (the first clip model is the ancestor box; M2's clip flag refines it); the deepest hit wins. Hidden and collapsed subtrees are skipped.

Focus (`focus.rs`): focusable nodes are buttons by default and anything `set_focusable`; the tab order is depth-first tree order inside the current scope (the nearest ancestor flagged `focus_scope`, else the root), wrapping at the ends; disabled, hidden and collapsed nodes, and nodes under a hidden or collapsed ancestor, are skipped; `focus` into a different scope records the previous focus, which `remove` of that scope root restores when it is still valid; removing, hiding, collapsing or disabling the focused node clears focus, and so does removing, hiding or collapsing any of its ancestors, so `focused()` never names a node the traversal would skip. M3 drives this from the `ui_*` actions; M1 exposes the calls.

```rust
// crates/tungsten-core/src/ui/measure.rs — the fixed-advance test double; public, since games' tests use it
pub struct FixedAdvanceMeasure { advance_em: f32 /* 0.5 by default */, nodes: Vec<Option<(StyledText, TextStyle, Option<TextMetrics>)>>, free: Vec<u32>, pub counts: MeasureCounts }

```

Its rules, chosen to match the engine's modes (A3): a glyph advances `size × advance_em` plus letter spacing; newlines end lines; max-content is the widest unwrapped line; min-content is the widest word under `Word` and `WordOrGlyph`, the widest glyph under `Glyph`, the unwrapped width under `None`; a definite width wraps greedily per mode (a word wider than the box overflows under `Word`, breaks inside under `WordOrGlyph`); height is `line_count × line_height`; the first baseline is `0.8 × line_height`; empty text measures one line height (w01 §4); a stale ID measures `TextMetrics::default()`; nothing is rounded; overflow and ellipsis are ignored, since no M1 test needs them.

- Step 1's verdict is neither: Taffy fails a case and the README shows the hand-rolled layout cannot meet the same cases in one session. Stop; the owner decides.
- The API review asks for more than renames and defaults (a different seam, a second resource, closure builders now): stop after recording the request under §4; the owner reruns the plan prompt or amends this plan.
- A change outside §files to touch is needed, `crates/tungsten/src/app.rs` above all.
- `just deps` fails on Taffy's graph (an advisory, a licence outside the allowlist or a banned duplicate): stop; the owner decides between a pinned exception and the hand-rolled layout.
