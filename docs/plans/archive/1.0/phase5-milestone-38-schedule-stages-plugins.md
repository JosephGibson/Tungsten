## 2. Design

The API as the spike prototyped it and the gate fixed it (`D-128`), with this plan's deltas marked *delta*. Level C: the owner reviews this sketch and the template diff after step 1; names are the review's.

### Core: `tungsten_core::schedule`

```rust
pub enum Stage { Startup, PreUpdate, FixedUpdate, Update, PostUpdate }   // closed; Stage::ALL; name() -> "startup" …
pub type SystemFn = Box<dyn FnMut(&mut World)>;
pub fn system(name: impl Into<String>, run: impl FnMut(&mut World) + 'static) -> SystemDesc;
impl SystemDesc {
    pub fn name(&self) -> &str;
    pub fn before(self, other) -> Self;            pub fn after(self, other) -> Self;             // required: a missing name fails resolve
    pub fn before_if_present(self, other) -> Self; pub fn after_if_present(self, other) -> Self;  // applies only when `other` exists
}
impl Schedule {
    pub fn new() -> Self;
    pub fn add(&mut self, stage: Stage, desc: SystemDesc);  pub fn add_fn(&mut self, stage, name, run);
    pub fn resolve(&mut self) -> Result<(), ScheduleError>;  // per stage: Kahn's algorithm, earliest-registered ready first
    pub fn run_stage(&mut self, stage, world: &mut World, observe: impl FnMut(&str, Duration));
    pub fn names(&self, stage) -> impl Iterator<Item = &str>;  pub fn resolved_text(&self) -> String;  // "stage: a, b, c" per line, "-" when empty
    pub fn len / is_empty / contains(name) / stage_of(name) / is_resolved
}
pub enum ScheduleError {
    DuplicateName { name, first: Stage, second: Stage },
    UnknownName { system, stage, relation, missing, reason },   // reason names the other stage
    Cycle { stage, path },
}
pub trait Plugin: 'static { fn build(&self, schedule: &mut Schedule, world: &mut World); fn name(&self) -> &'static str { type_name } }
impl PluginSet { pub fn new(); with<P: Plugin>(self, P) -> Self /* replaces a same-typed plugin in place */; without<P>(self) -> Self;
                 contains::<P>(); names(); len(); is_empty(); build(self, &mut Schedule, &mut World) }
```

- `[a, b, c.before(a), d.after(c)]` resolves to `b, c, a, d`; ties keep registration order, so the text is deterministic for a registration sequence.
- The three errors read: ``system `a` is registered twice, in `update` and `post_update` ``; ``system `walk` in `update` runs after `physics_step`, which is in `fixed_update` ``; ``stage `update` has an ordering cycle: a -> b -> a``. *delta, landed* The cycle reporter walks unresolved *predecessors* from the first unresolved node (every unresolved node has one, which is why Kahn's algorithm left it) until a node repeats; that node is on a cycle even when the start merely waits behind one, and the tail is reversed into run order. The spike's walker followed successors and `expect`ed one, which a system blocked only by an upstream cycle (`sink.after(a)` with `a.after(b)` and `b.after(a)`) lacks, a panic that a release build turns into an abort (2.1); the walker now has no panic path.
- `World::register_event::<T>()` (idempotent, returns whether `T` was new), `has_event`, `registered_event_count`, `flush_events()`; the flushers are `fn(&mut World)` pointers on `World` (`D-040` as amended).
- `tungsten_core::inspect::{InspectFn, InspectRegistry}`: a `World` resource with `register::<T: Inspectable>(label)`, `register_with(label, fn)`, `iter`, `len`, `is_empty`.
- `tungsten_core::physics::plugin::{PhysicsPlugin, PHYSICS_STEP = "physics_step", PHYSICS_SYNC = "physics_sync"}`: registers `CollisionEvent`, `physics_step` in `FixedUpdate`, `sync_position_to_transform` in `PostUpdate`; re-exported from `tungsten_core::physics`.
- *delta, landed* `tungsten_core::display::WindowSize` (Q6), re-exported at `tungsten_core::WindowSize`, and from the umbrella at `tungsten::WindowSize` and `tungsten::app::WindowSize` (`pub use tungsten_core::WindowSize` in `app.rs`), so no caller changes; its derives are the old ones (`Debug, Clone, Copy`).
