## Context digest

M1 (0.50, `D-125`) built the model: one `UiTree` resource, layout through Taffy behind core's own styles, a theme-token style model, hit testing and focus, the `TextNodeStore` seam into the render crate's retained text nodes, and the headless `UiHarness`. Nothing draws. The glyph gate (`D-126`) chose T1b: one glyphon `TextRenderer` per paint-list text batch on one shared atlas, `trim` only before a frame that re-prepares every batch, forced every K frames and on `AtlasFull`, a failed batch not drawn, K 16 to start; it also fixed the DPI model (`D-127`): logical UI units, one rounding rule at extraction shared by primitives and glyph clips, text laid out in logical units and rasterized at physical size through `TextArea.scale`. W8a (`D-142`) gave captures a result, so a pixel test can compare the direct and capture paths with UI visible, and W2 R2 (`D-145`) split the frame around the acquire: the overlay pass sits after the split, in the second command buffer, which is where the UI draws. M0b (`D-144`) added the `ScaleFactor` resource M2 applies.

M2 is the rung every later rung shows on screen: M3 routes input into what M2 paints, M4 builds screens, M5 moves the debug views onto it, WL draws world labels as one paint-list batch in the lowest layer. The plan carries the prototype's three findings (a draw after `AtlasFull` fails validation; etagere frees a bucket only when every glyph in it is gone, so K is finite; glyphon evicts before it grows) and the K telemetry, with one gap: glyphon 0.12 exposes no atlas size (Q3).

## 2. Design

API sketch, reviewed after step 1 (level C). Core defines plain data and never calls render (`D-007`, `D-018`); render consumes a `&PaintList`; the umbrella lends the text engine to layout, as M1 arranged. API review 2026-10-13: approved as step 1 implemented it; the core block below is the implemented surface (the sketch's `#[derive(Default)]` on `PaintList` became a manual impl at scale 1.0, `dump` prints the clip table first, `set_theme` resets `theme_id`, an `Image` is a leaf, theme-file variants merge over the built-in variant, `sprite_epoch` moves only for a registered sprite, and the helpers marked `+` were added).

**Core (`tungsten_core::ui`, step 1).**


`rect` in a command is already physical (`Rect` of `f32`, `min = rect.min · scale`); clips are integer. A node paints its own `Rect` when its fill or border is visible, then its children; a `Label` paints `Text` at its box with the resolved text colour; an `Image` paints one `Image`, or nine when the sprite has nine-slice insets (corners at source size times `scale`, edges and centre stretched; no repeat, w01 §6). A node with `clips_children` pushes the intersection of its box and the current clip; an empty intersection skips its children. Hidden subtrees paint nothing and keep their boxes; the focus ring is the kind's `focused` border, already resolved (Q7). A `Text` command's effective bounds are its own box intersected with its clip, as the section path clips a section to its bounds today, so an unwrapped or overflowing line never leaves the box the partition rule reasons about (critique 2.3). `text_batches` is w01 §6's partition rule turned around (step 6: as written, a label over its own panel closed the batch, seven batches for the lab's three roots): a batch opens at a text command and every later text command joins it; a non-text command over any of the batch's text rects closes the batch before itself (pairwise; a bounding box split a row of buttons at every button); a batch draws where it closes, after the non-text commands inside its range, which overlap none of its text. `dump` is the snapshot format, one line per command: `Rect (x, y) w×h fill #rrggbbaa border #rrggbbaa 1.0 r 4.0 clip 0`, `Image (x, y) w×h tex 3 uv (…) clip 1`, `Text node 2:0 (x, y) w×h #rrggbbaa clip 1`, with `-- batch n` lines where `text_batches` splits.

Theme file (Q9), every field optional over `Theme::default()`, colours `#rrggbb` or `#rrggbbaa`, authored in sRGB and kept as `[u8; 4]`:

```json
{ "tokens": { "colors": { "surface": "#1e1e24", "text": "#f0f0f5", "accent": "#5b8def" },
              "spacing": { "md": 8 }, "radii": { "md": 4 }, "fonts": { "body": "sans", "mono": "mono" },
              "text": { "size": 14, "line_height": 18 } },
  "kinds": { "button": { "normal": { "background": "#2b2b33", "border_width": 1, "text": { "weight": 600 } },
                         "focused": { "border": "#ffffff" }, "disabled": { "text": { "color": "#808090" } } } } }
```

`kinds` default from `KindStyles::for_tokens(&tokens)`, then each named kind's `normal` fields and variants override. The manifest gains `ui_themes: { "<id>": { "path": "ui/themes/<id>.json" } }` (`ResolvedUiTheme { path }`), and `SpriteEntry` gains `nine_slice: [left, top, right, bottom]` in source pixels (Q5), carried to `ResolvedSprite` and `SpriteAsset`; `register_sprite` keeps its signature and `AssetRegistry::set_sprite_nine_slice(id, insets)` sets it after registration, as `update_sprite_lit_atlas` sets the lit marker. `AssetRegistry::sprite_epoch() -> u64` rises on `register_sprite`, `update_sprite_entry`, `update_sprite_lit_atlas` and the new setter, never on interning, so a retained paint list knows when a repack moved a UV. `UiThemeRegistry` (ID → `Theme`) is a core assets resource the loader fills.

`UiTree::layout` records the viewport it last laid out at and, when the viewport differs, marks every root for layout before the pass, as it does when the font epoch moved (critique 1.2): a static UI follows a resize, and its clip 0 with it.

**Render (`tungsten_render::ui`, steps 2 and 3).**

```rust
#[repr(C)] pub struct UiInstance {   // 80 bytes; shadow and gradient fields reserved, zero in M2 (Q13)
    pub position: [f32; 2], pub size: [f32; 2], pub uv_min: [f32; 2], pub uv_size: [f32; 2],
    pub fill: [u8; 4], pub border: [u8; 4], pub border_width: f32, pub corner_radius: f32,
    pub shadow_offset: [f32; 2], pub shadow_blur: f32, pub shadow_color: [u8; 4],
    pub gradient_color: [u8; 4], pub gradient_dir: [f32; 2], pub flags: u32 /* bit 0: textured */ }
pub struct UiPipeline;  // ui.wgsl: group 0 viewport uniform, group 1 the sprite pipeline's texture layout (a 1×1 white page for untextured)
impl UiPipeline { pub(crate) fn upload(&mut self, device, queue, list: &PaintList) -> Vec<DrawItem>; pub(crate) fn draw_batch(&self, pass, batch, textures) }
pub(crate) enum DrawItem { Primitives { texture: Option<TextureHandle>, clip: u32, instances: Range<u32> }, Text { batch: usize } }
```

`ui.wgsl` is internal, beside `quad.wgsl`: a unit quad per instance, the rounded-rectangle signed distance for fill and border with one-pixel analytic anti-aliasing, the texture sample times the tint, colours decoded from sRGB to linear in the shader so panels match glyphon's `Accurate` text (Q8), straight-alpha blending, no depth, single sample (the overlay target). The UI draws in the overlay pass after the split: `draw_items`, built at prepare, interleaves primitive batches (one per run of commands sharing texture and clip) and text batches in paint order, then the HUD, systems overlay and inspector sections as today (Q14). Every item carries the scissor the draw sets before it: a primitive batch its clip, a text batch and the sections the whole viewport, since glyphon clips through `TextBounds` and its `render` leaves the pass's scissor as it finds it (critique 1.4). The draw intersects each scissor with the attachment's size at record time and skips an item whose intersection is empty: the acquire can shrink the surface before the resize reaches the world (`sync_surface_to_window`), and the paint list was extracted before it (critique 2.1); glyphon clamps `TextBounds` to the viewport itself. `render_frame_full` and `render_frame_full_timed` take `ui: &PaintList` after `text_sections`; `render_frame` and `render_frame_with_quads` pass an empty list; `FrameDraws` gains `ui`. The pass keeps its descriptor label and the timing label `text` (Q1). A frame with an empty list records no UI draw, uploads nothing and changes no pass or target.

Text batches (step 3, `D-126`): `TextPipeline` keeps `batch_renderers: Vec<TextRenderer>` (one per batch index, grown and never shrunk), each batch's signature (every text command's position, size, colour, node and node revision, and its clip's rectangle looked up through `clips`, never the index; critique 1.5) and `changed_frames_since_full`. `TextEngine` nodes gain a `revision` bumped by a changing `set_text` and by `commit_layout`, and `node_area(id) -> Option<(&Buffer, u64)>` for a committed node under the current epoch. `prepare(device, queue, sections, ui, width, height)`: a frame is **full** when `force_full` is set (a previous `AtlasFull` or `reload_font`), when the font epoch moved, or when `changed_frames_since_full >= K` (16, a `const`; Q2); a full frame calls `atlas.trim()` first and prepares every batch and the sections; otherwise only batches whose signature changed, and the sections when the engine's `update` says so. A frame that prepared nothing advances no counter. A batch index the frame's list does not have loses its signature, so a batch that disappears (F6, a removed window) and returns re-prepares rather than drawing vertices whose atlas slots a full frame may have recycled (critique 2.2). A batch whose `prepare` returned `AtlasFull` is marked failed and not drawn, and `force_full` is set. `post_frame` no longer trims. With no UI batches the rule is today's: every changed frame is full, so the benchmark rows prepare and trim exactly as before. `TextStats { batches, prepared, full_frame, forced, atlas_full_total, full_frames_total }` comes out through `Renderer::text_stats()` (Q3).

**Umbrella (steps 4 and 5).** `App::with_plugins` inserts `UiTree`, `UiDebug` and `UiThemeRegistry`. `run_frame` gains `stage_ui_layout` after the post-AA apply and before the extract: viewport `WindowSize / ScaleFactor::get()`, `renderer.text_nodes()` as the store; with no renderer (the harness) it does nothing, and `UiHarness` keeps its own post-frame layout. Its time counts in `extract` (Q11). `stage_extract` repaints into the app's retained `PaintList` when the tree is paint-dirty, or when the scale, the `UiDebug` value or the registry's `sprite_epoch()` differ from the ones recorded at the last paint (`PaintedAt { scale, debug, sprite_epoch }`), so a static UI follows F5 and F6 and an atlas repack (critique 1.3); `FrameExtract` and `FrameDraw` gain `ui`. `UiHarness::paint() -> PaintList` and `dump_paint()` paint the tree at scale 1 with the world's `UiDebug` and registry. `ui_debug_toggle_system` (`PreUpdate`, in `DebugOverlayPlugin` beside the HUD toggle) flips `UiDebug` on `engine_toggle_ui_bounds` (F5) and `engine_toggle_ui` (F6) (Q10). `RenderCounts` gains `ui_commands`, `text_batches`, `text_batches_prepared`, `text_full_frames` and `text_atlas_full`, and the HUD gains a `ui` row. The loader fills `UiThemeRegistry` from `ui_themes`, warning on a `fonts` token naming no `font_families` entry, and carries nine-slice insets into `SpriteAsset`. A changed theme file reloads through `reload_ui_theme(id, path, world)`: the registry entry is replaced and, when `UiTree::theme_id()` is that ID, `set_theme_asset` runs again; a manifest reload adds new theme entries and keeps removed ones stale, as sprites do.

**Fixture (step 6).** `examples/05_ui_lab` (package `example-05-ui-lab`): a HUD root on the Game layer (a panel with a live frame counter in tabular figures and an icon), a window root (title, wrapped body text, two buttons, a nine-slice frame), a second window on the GamePopup layer overlapping the first so its text paints over the first's panel (two text batches), and the hot-reloaded theme `ex05_default` from `assets/ui/themes/ex05_default.json`.
