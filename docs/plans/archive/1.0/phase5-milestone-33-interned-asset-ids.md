## Context digest

R0 is the serial half of W2 (criteria §5.3): it lands before the R1 spike so that the spike's serial baseline has no string compares in it (implementation plan §3, W2 R0 note). After `D-086`, the string compare of sprite IDs is the largest cost left in `gpu-throughput`'s extract (13.28 of 14.68 ms `total`, criteria §5.2), and the extract still emits every sprite, in view or not. Each animation frame change clones a `String` and each particle spawn clones one, which ties `particles`' `animate_sprites` and the extract to the allocator's state ([benchmarks](../../../perf/benchmarks.md), "String sprite IDs").

`Sprite.asset_id: String` is public API, so the change is a break, the first row of W4's [break ledger](../../1.0/w04-api-freeze.md#break-ledger); level C, because this ID is what every game writes to name a sprite. It keeps `D-009`'s model: names in files and the manifest, never paths; the runtime handle is a dense ID, as materials (`MaterialAssetId`), shaders and particle configs and meshes (`AssetId<T>`) already have. Decisions cited: `D-009`, `D-016`, `D-017`, `D-018`, `D-042`, `D-046`, `D-073`, `D-086`, `D-103`, `D-107`. Expected: `D-113` (IDs), `D-114` (culling).

Later work expects: the R1 spike (Track B) measures on this tree; R1 splits pass 1 across workers, which an ID read by index makes simpler (no shared lookup cache); W13's animated sprite writes `Sprite.asset_id` from `AnimationState` (criteria §8.4), which this milestone makes a copy of an ID.

## 2. Design

The API sketch below is what step 1's review approves. Names follow the registries' existing ones. Rustdoc goes on every new or changed public item.

```rust
// tungsten-core::assets, re-exported at the crate root like ParticleMeshAssetId
/// Dense sprite handle, minted by `AssetRegistry`; stable for the registry's life.
pub type SpriteAssetId = AssetId<SpriteAsset>;

#[derive(Debug, Clone, Copy)]                    // Copy is new (Q6)
pub struct Sprite {
    pub asset_id: SpriteAssetId,                 // was String
    pub color: [u8; 4],
    pub z_order: i32,
    pub material_id: Option<MaterialAssetId>,
}
impl Sprite { pub fn new(asset_id: SpriteAssetId) -> Self; /* with_material unchanged */ }

impl AssetRegistry {
    /// Same name, same ID, registered or not (Q2). An unregistered ID draws nothing.
    pub fn intern_sprite(&mut self, name: &str) -> SpriteAssetId;
    /// Interns `names` in sorted order, so a name set gets the same IDs every run (A4).
    pub fn intern_sprites<'a>(&mut self, names: impl IntoIterator<Item = &'a str>);
    pub fn sprite_id(&self, name: &str) -> Option<SpriteAssetId>;      // lookup only
    pub fn sprite(&self, id: SpriteAssetId) -> Option<&SpriteAsset>;   // index, no hashing
    pub fn sprite_name(&self, id: SpriteAssetId) -> Option<&str>;
    pub fn register_sprite(&mut self, name: String, /* unchanged */) -> SpriteAssetId; // returns the ID; D-017 panic stays
    pub fn sprite_names(&self) -> impl Iterator<Item = &str>;          // was sprite_ids() (Q5)
    pub fn sprite_name_for_path(&self, path: &Path) -> Option<&str>;   // was sprite_id_for_path (Q5)
    // get_sprite(&str), update_sprite_entry(&str, …), update_sprite_lit_atlas(&str, …) unchanged
}

pub struct AnimationFrame { pub sprite: SpriteAssetId, pub duration_ms: u32 } // file keeps "sprite": "<name>" (Q3)
// AnimationData and AnimationFrame lose their public Deserialize impls: a private file
// struct parses the names, and load resolves them through the registry.
impl AnimationData { pub fn load(path: impl AsRef<Path>, sprites: &mut AssetRegistry) -> Result<Self, AnimationError>; }
impl AnimationState {
    pub fn current_sprite(&self, registry: &AnimationRegistry) -> Option<SpriteAssetId>;
    pub fn advance(&mut self, dt_ms: f32, registry: &AnimationRegistry) -> Option<SpriteAssetId>;
}

// tungsten::particles: the caller resolves the config's sprite name once (Q4)
#[allow(clippy::too_many_arguments)]
pub fn spawn_particle_via(cmd: &mut CommandBuffer, emitter_ent: Option<Entity>, config: Arc<ParticleConfig>,
                          sprite: SpriteAssetId, position: Vec2, velocity: Vec2, lifetime: f32, start_scale: f32);
```

- **Storage.** Names map to IDs; each ID indexes a slot holding its name and, once registered, its `SpriteAsset`. `sprite(id)` is a bounds-checked index: an ID past the end, or one interned and not yet registered, reads `None`. An ID means something only in the registry that minted it, the one `AssetRegistry` of an `App`'s world: another registry reads its own slot at that index, or `None` past its end. The rustdoc states this precondition, as it holds for `MaterialAssetId` and `AssetId<ParticleConfig>` today; provenance checks would cost a tag in every `Sprite` and a compare per lookup.
- **Interning, not registration, mints IDs (Q2).** A scene or animation may name a sprite that a later manifest reload adds; interning keeps `D-046`'s unresolved-at-spawn behaviour, and `register_sprite` fills the interned slot, so such an entity starts drawing then. Interning is append-only, which A3 makes safe: no registry is replaced in a session.
- **Order (A4).** `load_sprites` calls `intern_sprites` with the manifest's names before packing, and a manifest reload interns its added names the same way, so a manifest set yields the same IDs in every run. Nothing reads an ID's value for output: batch classes number by first use in query order.
- **Callers.** Game code interns once at spawn: `let hero = world.get_resource_mut::<AssetRegistry>().expect("registry").intern_sprite("hero"); world.insert(e, Sprite::new(hero));`. Scenes intern each entry's name before taking the `CommandBuffer` (A11). The animation loader and hot reload intern frame names through `AnimationData::load` (manifest validation already requires them to exist). The particle tick resolves `ParticleConfig.sprite` once per emitter per tick, interning when absent, and spawns with the copy; the public `spawn_particle_via`, which gets no registry (`crates/tungsten/src/particles.rs:471`), takes the ID as a parameter, and example 04 interns its streak sprite once (Q4). The extract reads `assets.sprite(s.asset_id)`; `AssetLookup` and `asset_cache_slot` go (A5). The lit-plus-material warning prints `sprite_name`. Core's `Inspectable for Sprite` prints `#<index>`; the umbrella's inspector registers `Sprite` with a reader that prints the name (Q12). Example 01 keeps `CurrentSprite(String)` and maps `advance`'s ID back to the name; its extract tests names through `sprite_name` (Q13).
- **Benchmark (Q9).** The bench writes IDs where it wrote names (`animate_sprites` copies the returned ID; walk clips and frames are interned once at startup). The work, the counters and the digests are unchanged, so no `workload_version` moves.
- **Culling (step 3).** The view is the one render projects with this frame. A windowed display request writes `WindowSize` at once while the surface resizes only on the `Resized` event (A7), so `WindowSize` can name a size render does not use. Before the extract, the app writes the renderer's surface size into a crate-private field of `ExtractScratch`; without a renderer (the harness, a bare `World`) the extract falls back to `WindowSize`. When `CameraState` and one of these sizes exist (Q7), pass 1 computes `camera.visible_world_aabb(width, height)` once and marks a sprite culled when its bound lies wholly outside it. The bound, after the parallax remap: unrotated, the box from `pos` to `pos + size` (either sign); rotated, a square of half-side `(|size.x| + |size.y|) / 2` about the centre, which covers every rotation. A sprite that touches the view is kept. Only sprites drawn by the stock sprite and lit pipelines are culled: a sprite with an effective material runs its shader's own `vs_main`, which may move the quad (`crates/tungsten-render/src/material.rs:42`, `:65`), so it is always kept.
- **Culled sprites keep their keys (Q14).** Within a z-run a class's batch opens at its first sprite in painter order and takes the class's later sprites (`crates/tungsten/src/sprite_extract.rs:411`–`:451`), and the renderer draws batches in list order. Dropping a culled class-opener would move its batch behind another class's, which changes the pixels of overlapping same-z sprites as the camera moves. So a culled sprite still gets its class and its sort key, flagged, and writes no instance: pass 2 opens batches over all keys, copies only kept instances, and drops batches left empty, which keeps the order of the rest. `z_norm` counts every key, so each kept instance is byte-equal to the uncull extract's, under `cpu_stable` and `gpu_depth` alike. What culling saves is the instance write, the pass-2 copy, the upload and the vertex work of each culled sprite; the key, class and sort costs stay.
- **Seam.** Core keeps opaque handles only (`D-016`); the extract still reads `&World` and returns plain data (`D-018`). `SpriteAssetId` is `Sync`, as `String` was, so R1's slices keep their bounds (criteria §5.4).
- **Template.** n/a: `templates/basic` arrives with W12a. The review in its place reads the sketch as landed and the `api/tungsten-core.txt` diff.
