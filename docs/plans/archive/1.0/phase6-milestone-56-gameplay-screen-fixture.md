## 2. Design

Level B: this section and the open questions settle the design; the steps are then mechanical. Core gains plain data and pure functions; the umbrella maps roots to states and bridges prewarm to the renderer; render consumes plain data and never reads the `World` (`D-007`, `D-018`).

### 2.1 Paint-only node properties, the root fade and frozen roots

- `UiTree::set_opacity(id, f32)` (clamped to 0..=1, NaN ignored), `set_translation(id, Vec2)` (UI units, non-finite ignored) and `set_scale(id, f32)` (clamped to 1/64..=64, non-finite or not positive ignored), with `opacity`, `translation` and `scale` getters (`None` for an invalid ID). Each marks paint only, never layout; an equal value marks nothing.
- Roots also take `set_fade(root, f32)` (0..=1, the transition's; a game may set it) and `set_frozen(root, bool)`; on a widget that is not a root both do nothing.
- Paint: a node's alpha is the product of the opacities on its path times its root's fade, multiplied into every colour it paints (fill, border, image tint, text colour; rounded). A subtree whose alpha is 0 paints nothing but stays hit-testable. A node maps its subtree by `p ↦ c + s·(p − c) + t` (`c` its layout centre, `s` its scale, `t` its translation rounded to whole physical pixels at the paint scale), composed down the tree. Rects, corner radii, border widths, nine-slice insets and clip rects transform. A text command draws with the composed scale S rounded down to a multiple of 1/32 (S itself when S < 1/32; Q4), in a box that is the exact transformed content box scaled by that ratio about its centre, so text never outgrows its box or its clips; a subtree whose composed scale is below 1/64 paints and hits nothing, so nested scales never round to zero. `PaintCommand::Text` gains `scale: f32` (a break, §2.11); `PaintList::dump` prints ` x<scale>` only when it is not 1, so existing snapshots stand.
- Render: `TextArea.scale` is `list.scale × command.scale`, and the batch signature includes the scale.
- Hit testing and the slider's pointer mapping use the same transforms, so the pointer agrees with what is painted (`D-149`'s rule); `UiTree::visual_rect(id)` returns that box; directional focus keeps layout rects.
- A frozen root keeps its look, is hit and blocks what is behind it, and a press over it is the UI's; its widgets take no press, activation, value change or focus move, a press it held is cancelled at the next routing, and no `ui_*` action acts in it: `ui_cancel` sends no `Cancel` for its scopes or for it as the modal root (the router's fallback at `route.rs:838-845` checks the freeze). A frozen modal root still takes every key press and keeps its ownership, so an Escape during a fade sends no `Cancel`, reaches neither `RoutedInput` nor gameplay, and does not exit.

### 2.2 Label colour, content box and disabled ancestors

- A label whose resolved text style changed in colour alone marks paint and is not re-set (amends `D-125`'s colour clause). Render's text node bakes no style colour into its attributes, so glyphs take the area's default colour, the paint command's colour times the alpha; a span with its own colour keeps it and does not fade (Q3, a stated limit).
- UI F4: a label commits at its content box (its box less Taffy's border and padding) and its text command draws there.
- UI F2: a widget under a disabled ancestor applies its `disabled` variant, and `set_enabled` marks the subtree style-dirty.

### 2.3 UI animation tracks

- `UiTrack` (`#[non_exhaustive]`, in a new `ui/anim.rs`): `UiTrack::opacity(from, to, secs)`, `translation(from, to, secs)`, `scale(from, to, secs)`, `background(from, to, secs)`, `border(from, to, secs)` and `text_color(from, to, secs)`, then `with_easing(Easing)`, `with_repeat(TweenRepeat)`, `with_direction(TweenDirection)` and `with_tag(u32)` (Q2), reusing core's tween enums (`D-054`). `UiProperty` (`#[non_exhaustive]`) names the six properties.
- `UiTree::animate(id, track)` writes the start value at once and replaces a running track on the same property without an event (Q14); `stop_animation(id, property)` leaves the property where it is; `is_animating(id)`. A track whose value is not finite, or a scale that is not positive, is refused with one warning; a duration that is not finite or not positive finishes at the next tick on its end value. Removing a widget drops its tracks.
- A track writes its property each tick: opacity, translation and scale through §2.1's setters, colours through the node's `StyleOverrides`, so a finished track's value stays. None of the six relayouts.
- `ui_animate_system` ticks every track on `Time::real_delta()` (UI runs on the real clock, `D-129`), so a paused game animates its pause menu; easing per `Easing::apply`; `Loop` and `PingPong` never finish and `Times(n)` after n cycles, the remainder carried across cycles (unlike the tween tick's known issue). A finished track sends `UiEvent::AnimationFinished { widget, property, tag }`, read with `EventQueue::<UiEvent>::animation_finished(widget, tag)` on the current window.

### 2.4 State-owned roots and the transition fade

- `StateStack::own_root(root, RootCover)`: called from a state's hook or `update`, the state being dispatched owns `root`; elsewhere the top state does; a widget that is not a root, or an empty stack, warns and is ignored. Ownership is per stack instance (by stack index), so two instances of one `StateId` keep their own roots, unlike `SceneEntity`.
- `RootCover::Hide` hides the root while another state covers its owner, `Show` keeps it shown and frozen; resuming restores the visibility the root had when it was covered and unfreezes it.
- Pop and replace remove the exiting state's roots after its `on_exit`. Push applies the cover after the covered state's `on_pause`.
- While a transition is queued or active (`StateStack::is_transitioning`) every owned root is frozen and takes `fade = 1 − transition_cover()` (1 while only queued); at its end the fade returns to 1 and the cover rule decides the freeze. The transition pass covers the frame, and the UI draws after it (`D-093`), so fading every owned root keeps the UI in step with the scene. Roots no state owns are untouched.
- One function syncs this, called at two points: at the dispatcher's end, after the top state's `update`, so the frame paints with its own fade and a root owned in a hook starts at it; and by `UiPlugin`'s `ui_state_roots` system before `ui_route`, so a transition an `Update` system queued after the dispatcher (`crates/tungsten/src/app.rs:1161-1167`, `state.rs:121-130`) freezes the roots before the next routing. With no owned roots it returns at once (at the dispatcher's end, the bench rows' only new work).

### 2.5 The schedule

`pre_update: …, display_input, ui_state_roots, ui_route, ui_animate, state_dispatcher` (Q1): `UiPlugin` registers the umbrella's `ui_state_roots` with `before(UI_ROUTE)` (§2.4), `ui_route` with `before_if_present(STATE_DISPATCHER)` and `ui_animate` with `after(UI_ROUTE)` and `before_if_present(STATE_DISPATCHER)`, with `UI_STATE_ROOTS` and `UI_ANIMATE` in core's names. Both constraints are needed: the scheduler takes the earliest-registered ready system (`crates/tungsten-core/src/schedule.rs:407`) and `StatePlugin` registers first, so without the second `ui_animate` would run after the dispatcher; with both, the order holds whichever order the plugins register in. A state's `update` then reads this frame's routing, `activated()` and `RoutedInput` included, which settles `D-149`'s open limit (amends its placement clause); a track a state adds in `on_enter` shows its start value for one frame and ticks from the next. The bench, without `UiPlugin`, keeps its order.

### 2.6 Binding labels and prompts

- `Binding::label(self) -> Cow<'static, str>`: key names follow the physical `KeyCode` (`W`, `Space`, `Enter`, `Esc`, `Tab`, `Up`, `F5`, `Left Shift`, `Page Up`, …; an AZERTY player sees US labels, since winit 0.30 has no keymap query), mouse (`Left Mouse`, …), wheel (`Wheel Up`), pad buttons Xbox-style (`A`, `B`, `X`, `Y`, `LB`, `RB`, `LT`, `RT`, `Select`, `Start`, `Home`, `LS`, `RS`, `D-Pad Up`, …; Q7) and stick directions (`Left Stick Up`, …). Tables sit beside the `input.json` names in `key_serde.rs`.
- `UiTree::set_prompt(id, template)` on a label or a button's label: `{action:NAME}` placeholders, every other brace literal. The binding shown is the first of the last device's kind (`Keyboard` and `Pointer`: key, then mouse, then wheel; `Gamepad`: pad button, then stick), else the first of any kind, else `Unbound` (Q8). `set_text` on the label clears its prompt.
- `ui_route_system` resolves prompts after each routing: a prompt whose device or bindings differ from its last resolution is rebuilt and set; an unchanged one costs slice compares and no allocation. Comparing bindings rather than a revision catches the reload's whole-map replacement (A13) and `replace_bindings` alike. A prompt set after the frame's routing resolves at the next one and shows its literal text with each placeholder empty until then.

### 2.7 The capture-next-input mode

- `UiRouter::capture_next_input(widget)` (from the next routing), `cancel_capture()` and `capturing()`. While a capture is pending, every key, mouse button, pad button and stick direction press is the UI's (`wants_keyboard` holds) and none navigates; the first that is not an OS repeat ends the capture with `UiEvent::InputCaptured { widget, binding }` (read with `EventQueue::<UiEvent>::input_captured(widget)`), and its release stays the UI's, so neither the routed view nor the game sees half a press. Escape is captured like any key (Q9); the wheel is neither captured nor routed (Q10); a key with no `input.json` name is reported, and persisting skips it as `D-159` says.
- Focus loss, `cancel_capture`, a new capture, or the widget removed, hidden, disabled or frozen ends it with `UiEvent::CaptureCancelled { widget }`.
- The screen is the game's: the fixture replaces only the bindings of the captured kind (keys and mouse, or pad), keeps the rest, and persists through the user layer (`D-159`).

### 2.8 Text scale and allocation-free text

- `UiTree::set_text_scale(f32)` (clamped to 0.25..=4.0, non-finite or not positive ignored) multiplies every label's size and line height where the style is consumed (`prepare_text`) and a control's natural size, keeping resolved styles and their inheritance unscaled; a change marks every label stale and every root for layout.
- `Settings::text_scale()` and `set_text_scale(Option<f32>)`, clamped to `Settings::TEXT_SCALE_RANGE` (0.75..=2.0, Q13), the file's `text_scale` key (an older build ignores it, as unknown keys are); `apply_settings` sets the tree's scale, an unset value 1.0, and `App::new` sets a saved one on the tree it inserts (`crates/tungsten/src/app.rs:232-239`, `:287` apply each setting at startup, not `apply_settings`), so a restart keeps it (amends `D-159`'s settings list).
- `UiTree::set_plain_text(id, &str) -> bool`: a one-span label equal to the text returns `false` without allocating, so a live label written with `write!` into a retained `String` costs a format and a compare (w01 §14).

### 2.9 Prewarm

- `UiTree::prewarm(root)` asks for a one-shot raster of the root's text runs, shown or hidden, once it is laid out; a collapsed or removed root drops the request. `UiTree::paint_prewarm(scale, out) -> bool` paints the text commands of the roots asked for at their current transforms into a `PaintList` and clears those requests. A declared character set, such as a HUD's digits, is a hidden label in a prewarm root.
- The app paints the prewarm list at extract when a request is pending (`FrameDraw::ui_prewarm` records it), and before the frame's prepare calls `Renderer::prewarm_ui_text(&list) -> TextPrewarm` (`#[non_exhaustive]`: runs, glyphs, microseconds), which updates the viewport to the surface size, prepares the runs on a scratch glyphon renderer on the shared atlas, never drawn, and logs `UI prewarm: <runs> text runs, <glyphs> glyphs in <ms> ms` (w01 §10's cold start). Same positions and scale give the same glyph keys, so the first open's prepare finds them; they stay until the atlas needs their room after a full frame's trim (a stated limit, `D-126`). An `AtlasFull` result counts toward the trim rule as a batch's does.
- The atlas's byte size stays unreadable (glyphon 0.12); no 1.0 screen needs it, so the known issue moves to the T2 backlog row (Q16).

### 2.10 The fixture

The UI lab's interactive run becomes a `play` state owning the lab's roots (`Show`), plus a HUD row with a live timer through `set_plain_text` and a prompt `Press {action:state_pause} to pause`; `state_pause` (P, and Start added in code) pushes a `pause` state behind a fade: a modal "Paused" menu (Resume, Settings) with a prompt row, owned with `Hide`, its first button focused, `ui_cancel` resuming.
