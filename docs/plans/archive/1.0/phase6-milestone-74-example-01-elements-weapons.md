## 2. Design

### 2.1 The kit (step 1, level C)

Five additions, each additive, with rustdoc and no break-ledger row. They join the root re-exports (`lib.rs:286` and the damage block) and the prelude beside their neighbours.

```rust
// damage/effects.rs
impl Effects {
    /// Names `source` as the source of the active instance numbered
    /// `serial` (`EffectInstance::serial`); `None` clears it. A save holds
    /// no entity, so a game's load names each source again this way, from
    /// the game's own ID for it, before the next step: the instance's later
    /// payloads and its `on_expire` then come from `source`. Nothing else
    /// changes: stacks, time, factor, modifiers and granted tags stay.
    /// False, changing nothing, when no active instance has that serial.
    pub fn set_source(&mut self, serial: u64, source: Option<Entity>) -> bool;
}

// present/labels.rs
/// Floats `amount` at `anchor`, a world point, in `style`, as a cue's
/// `label` action does: for a number a game's own code shapes (a crit's
/// size, ticks summed over a window). The text is the amount, whole as
/// `3`, else to one decimal. Past 512 live labels the oldest goes; a World
/// without `CuesPlugin`'s labels takes none, and a non-finite amount or
/// anchor floats nothing.
pub fn float_label(world: &mut World, style: &LabelStyle, anchor: Vec2, amount: f32);

// damage/kinds.rs
impl DamageKinds {
    /// The style a `damaged_part` cue's style-less `label` floats a part of
    /// these kinds in, from the current `damage_types` entries: the deepest
    /// type's `label_style`, else its nearest ancestor's; `None` for no
    /// kinds or when no type of its line sets one.
    pub fn label_style(self, world: &World) -> Option<LabelStyle>;
}

// damage/ailments.rs
impl AilmentRung {
    /// The rung, skipped while the target carries any of `tags` or the
    /// step's feed has granted one to it already: a skipped rung leaves the
    /// bucket filling for the rungs above, as a chill that holds while the
    /// cold builds to a freeze. Each tag is checked as declared at load.
    pub fn with_blocked_by(self, tags: impl IntoIterator<Item = impl Into<String>>) -> Self;
    /// The tags that skip the rung.
    pub fn blocked_by(&self) -> &[String];
}

// damage/health.rs, set by the pipeline from the request (pipeline.rs:803-815)
pub struct DamagedPart {          // #[non_exhaustive], so a new field is additive
    // …the fields it has…
    /// The part's hit was a critical one (`DamageRequest::with_crit`).
    pub crit: bool,
}
impl DamagedPart {
    /// The event, a critical hit's part when `crit`.
    pub fn with_crit(self, crit: bool) -> Self;
}
```

The `effects` scene description's text stays, so the components snapshot's `effects` lines do not change.
- The rung's data form gains `"blocked_by": ["status.chilled"]` (default empty), each a tag name at deserialization and declared at load under `<type>.ailments.<i>.blocked_by.<j>`, beside `requires`. The `ailment_rung` shape's description gains the field, so `api/tungsten-kit-components.txt` gains its line and nothing else changes there. A skip is silent, as an unmet `requires` is: no new trace kind, so `crates/tungsten/src/tests/kit.rs`'s trace story stays as it is.
- Doc examples name no fixture damage type (the genericity scan, `coverage.rs:178`).
- Tests, kit side: `set_source` restores a source by serial after a JSON round trip (a periodic tick's `Damaged.source` and an `on_expire`'s instance follow it; an unknown serial returns false and changes nothing); `float_label` floats one label at the anchor in the style, drops the oldest past the cap, and floats nothing without the resource or with a NaN; `label_style` follows the deepest type, then its ancestors, and returns `None` for no kinds; a steady stream of small cold parts chills, then freezes when the chill rung is `blocked_by` its own tag, and stays chilled without it; a `blocked_by` grant pending from an earlier part of the same step skips the rung; an undeclared `blocked_by` tag fails the load with its field path; every part of a crit request carries `crit`, and a periodic or plain one's never.

### 2.2 The damage model

### 2.3 Targets and bodies

- **Targets** (with `Health`) take the kit's model whole: the ladders put burning, chilled, frozen, shocked, stunned and bleeding on them; 01 reads their `status.*` tags for overlays and physics. In `React`, through a cursor on `DamagedPart`, a fire part on a target that was frozen and a cold part on one that was burning queue thermal shock's explosion and a steam burst, dead or alive, "was" meaning when the step's resolve began: the last system of 01's `Overlap` records which targets carry `status.frozen` and `status.burning`, so effects the step's own parts apply later never react to earlier parts (Q24). `shattered`'s `EffectApplied` queues a shatter. A target that dies ends in one burst (§2.9). A dummy is a dynamic body throughout, under the iron friction rule: resting friction as iron's; frozen, ice friction (`FROZEN_FRICTION`) and the black hole's pull at iron's share; thawed, the hole leaves it be.
- **Bodies** (small and bowling balls, iron blocks, scraps) keep 01's components, because the pipeline ignores them (A4) and 12,000 balls each with `Effects`, `Tags` and buckets would cost the step and the save (Q1): `BallBurn` as today; `Chill` extended from iron to balls under the ice spray (1.5 s of exposure, as iron); `Frozen` gains a thaw clock (5 s, Q17) for iron, scraps and balls. A frozen ball draws in an ice shell (`ex10_ice_shell`) under a cold tint.
- **The endings**, one rule each, any frozen thing:
  - thermal shock: a fire hit (a fire part on a target, a blast's heat, a fire contact or the flamethrower on a body) on a frozen thing queues an explosion at it: fire and physical parts with knockback to targets in reach, small balls in reach lit, frozen things in reach hit by its fire (so the chain runs), bodies pushed; the frozen thing ends: a frozen ball is destroyed, frozen iron becomes its sixteen scraps (today's `shatter_iron`), a frozen scrap becomes chips, a frozen target's `frozen` ends. Starting reaches and parts in §2.10.
  - shatter: on a target, the `shattered` rung (physical past the threshold while frozen); on a body, a hard impact (§ impact); shards, no explosion.
  - impact: a body of at least a bowling ball's mass (8) meeting a frozen thing, or a frozen thing landing, at a closing speed of at least `SHATTER_SPEED` (600 px/s) shatters a frozen body, so small balls flying in a pile break no ice; a frozen target takes the impact as physical damage (below), which climbs the `shattered` rung. Today's rule, iron head-on at 600 px/s (`brick.rs`), is the iron case of this one.
- **Steam**: a cold hit (a cold part, the ice spray on a body) on a burning thing queues a steam burst at it: a wide push with fire and physical parts that, when its entry runs, first ends `burning` on targets in reach and applies `doused` to them at once, so its own fire resolving later in the step cannot light them again, and puts out burning bowling-sized things; burning small balls in reach are queued for their own bursts, and a small ball that bursts is destroyed, so bursts chain through a burning pile. (c)'s wisps freeze instead.

### 2.4 Cascades

- `features/elements/cascade.rs`: a `Cascades` resource, saved whole: a step counter, a strike counter and the entries, each `{ kind, target, at, origin, source, strength, due }`, a jump's also `{ strike, chain }` (`kind` one of explosion, shatter, steam, jump; `target`, `source` and `chain`'s members save IDs; `due` the counter's value from which it may run).
- **Order and cap.** `cascade_run`, in `Phase::Overlap` after 01's contact systems and before `kit_resolve`, increments the counter, then runs at most `CASCADE_CAP` (48) entries whose `due` has come, ordered by `(due, distance from origin, target save ID)`. An entry queued while the run executes is due on the next step, so a chain rolls one ring a step and its order does not depend on the frame rate. With an entry due, the run builds one bin of the step's bodies and targets (64 px cells) and scans nothing else; with none, it returns after the counter.
- **Bound.** An entry whose `(kind, target)` is queued already, a jump's `(strike, target)`, is not queued again, so the queue holds at most one entry a kind per live saved entity, and six jumps a strike; past `CASCADE_BOUND` (16,384) an add is dropped with one `log::warn!` a step and a count the tests read. A full pit's chain stays under it (step 4's test).
- **What runs it.** Explosions, shatters, steam bursts and conduction jumps (§2.6). An entry whose target is gone still runs its burst at its point; one whose target must change (a frozen ball to destroy) skips that part.
- **Sources.** Each entry carries the save ID it credits (the player in (b)); its requests take that entity as their source.

### 2.5 The frame rule

No kit request crosses a frame, since no save holds the kit's queues (A8): 01 builds and queues every damage and effect request in `Intent`, `Move` or `Overlap` (the sprays in `spells_cast`, the contact systems, `cascade_run`, the bullets' hits after `projectile_tick`), so the step's `damage_resolve`, `ailment_feed` and `effect_resolve` take them. 01's `React` systems queue cascade entries, sounds and presentation only. `missile_ends` moves from `React` to `Overlap` after `projectile_tick` (A18). Cue rules carry sounds, flashes and shakes, never an `effect` or `ability` action. The known-issues row in step 8 records the kit limit.

### 2.6 Lightning (slot 4)

- An ability `lightning` (30 mana, 0.8 s cooldown, the `casting` effect), pressed, refused before it spends anything with no cursor. The strike point is the aim point, or the nearest `conductive` body or target within 160 px of it, the rod (Q9). The bolt falls from the sky at that point's x and stops at the first solid on the way down: the nearer of a `cast_ray` down from the top of the level with bodies off (`SpatialFilter::with_bodies(false)`, tiles only) and the level's static colliders that the vertical line crosses, tested against their boxes, since a filter cannot tell a static body from a ball (`crates/tungsten-core/src/physics/query.rs:59-130`). Under a ceiling the strike hits the ceiling's top and never the aim point; balls, iron and targets never stop the bolt.
- The strike: 40 `damage.shock` to every target within 40 px of where it lands, the caster spared (Q9); it lights nothing (shock never ignites).
- Conduction, one chain a strike, decided a jump at a time, so ice that forms while a jump waits still stops it (Q21): the chain starts at the rod, else at the struck conductive thing nearest the strike point, and every thing the strike hit is already among its members; its first jump, due the next step, goes to the nearest conductive thing within 256 px not among them; each jump, when it runs, deals its strength (×0.7 a jump) to its receiver and, unless the receiver is frozen on arrival or the chain has made 6 jumps, queues the next the same way, its entry carrying the strike's number, the jump count and the chain's save IDs. The chain is one path, so a strike makes at most 6 jumps and none returns to a member. A frozen receiver, the chain's start included, takes its damage and passes nothing on, and shock starts no ending.
- Presentation: 5–8 of eight 24 × 64 segments stacked from the sky to the strike, each piece starting where the last ended, shown 0.15 s; one rendered frame of a violet-white veil over the view; a point light at the strike fading over 0.2 s; a `ShakeEvent` of 0.5, which the Screen shake option scales; thunder, and a crackle a jump. A jump draws as a zigzag of thin quads through 01's extract, no rotated raster.

### 2.7 The gun

- A `shoot` action (left mouse, RT), held to repeat at the cooldown. An ability `gun`: no cost, `charges { max: 12, refill: 1.2, all: true }` (the magazine, all back 1.2 s after the last round), 0.12 s cooldown, aimed, a `spawn` payload of the `bullet` prefab at 2,400 px/s (Q10).
- `bullet`: the kit's `projectile { range: 1600 }`, a trigger `hitbox` (damage 0), `linear_motion`, a tracer sprite and 01's `Bullet { ricochets }`. Adopted like the missile (a save ID in `PreUpdate` before `shell_save`).
- Hits: one decision a bullet a step, in 01's `gun_hits` in `Overlap` after `projectile_tick` (Q22), since the kit's pass alone finds the first wall, the range and the hurtbox hits (`projectile.rs:426-447`), and a stop moves the bullet back and zeroes its motion (`projectile.rs:619-640`). So 01 records each bullet's full-step segment before the pass (a `Move` system after the movers, into `Bullet`), and every contact is a fraction of that one segment (`projectile.rs:618-646` is the stop): the kit's hurtbox hit (`Struck`'s position) and its wall or range end (`ProjectileExpired`'s) projected onto it, and 01's first ball or iron contact, swept as the two bodies' relative motion over the same step (a ball from its `PrevPosition` to its `Position`). The earliest fraction wins. A hit first queues 6 `damage.physical` with 120 px/s of knockback through the hit builder (so it can crit). A ball first takes 900 px/s along the shot over its mass (a frozen ball shatters) and ends the shot: a shot the pass left alive through 01's despawn, one it ended already the kit's to despawn. Iron first turns the shot about the face it met, from the contact point, with ricochet sparks and sound, at most 2 times, when the pass left the shot alive; when the pass ended it beyond the iron, the shot ends at the iron. A `Struck` the decision passes over deals nothing, since the trigger hitbox queues no request itself (A3).
- The HUD's magazine beside the bar: the gun's icon, "rounds / 12" and a pip a round, greyed with "reloading" at 0, since the refill countdown is not public (Q20).

### 2.11 The save (schema 5)

- `SaveGame` gains `dummies` (each `{ id, map, position, velocity, health, resist, effects, sources, buckets, tags }`), `gone` (map objects removed: a dead placed dummy), `cascades`, `bullets` (step 6), `hints` and `summon` (step 7). `PlayerSave` gains `buckets` and `sources`. `sources` are `(serial, source save ID)` pairs read from `Effects::instances()` at capture and set back with `Effects::set_source` once every entity exists. - `gone` comes from a resource the run's start fills with the placed dummies' save IDs: one no longer alive at capture is gone.
- The coverage test gains the kinds `dummy` and `bullet`; each step that adds saved state extends `capture`, `restore`, `migrate` and the coverage lists in the same step, so `saves::` passes after every step.
