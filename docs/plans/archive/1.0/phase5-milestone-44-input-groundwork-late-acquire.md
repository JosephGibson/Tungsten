## 2. Design

### 2.1 M0b's API (level B: approved with the plan)

In `tungsten_core::input`, re-exported at the crate root:

- `KeyCode` gains Q2's 28 variants; `input.json` names equal winit's variant names (`D-045`). `Other(u32)`'s rustdoc: a key with no variant, whose number is stable within one build only and never serializes.
- `Modifiers`: a `Copy` set with private bits, `SHIFT`, `CONTROL`, `ALT`, `SUPER`, `empty`, `union`, `contains`, `shift()`, `control()`, `alt()`, `super_key()`.
- `RawInput`, `#[non_exhaustive]` and each struct variant too: `Key { code, pressed, repeat, modifiers }`, `MouseButton { button, pressed }`, `PointerMoved { x, y }`, `PointerLeft`, `Wheel { delta: WheelDelta }` (`Lines(x, y)` or `Pixels(x, y)`), `Modifiers(Modifiers)`, `Focus(bool)`.
- `RawEvent { seq: u64, input: RawInput }`, `#[non_exhaustive]`.
- `InputState` gains `raw_events() -> &[RawEvent]`, `focused()`/`set_focused()`, `modifiers()`/`set_modifiers()`, `pointer_in_window()`, `pointer_left()`, `suppress_until_release()`.

Rules (Q3–Q5). Every mutator applies its state and records its event, so the harness's input reaches the stream unchanged (A7): `key_down` of a held key records `repeat: true` and changes nothing; a move right after a move updates that record (same `seq`); `seq` counts up for the life of the `InputState`; `begin_frame` clears the stream. `set_focused(false)` releases every held key and button with release edges in both views, clears the modifiers and the suppression marks, and records `Focus(false)` alone. A key marked by `suppress_until_release` ignores its presses, recording nothing, until its release, which clears the mark and records nothing either. `pointer_left` keeps `cursor_position`, records `PointerLeft`, and the next move sets the position without a delta. Resize and scale changes stay resources, read by routing after the display changes apply ([w01](../../1.0/w01-ui-text-suite.md) §7).

In `tungsten_core::display`, re-exported: the resource `ScaleFactor`, default 1.0, with private fields: `os()`, `set_os()` (a non-finite or non-positive value is ignored), and `get()`, the factor layout will use: `os` times `ui_scale`, a setting W11b adds; until then `get() == os()` (`D-127`).

### 2.2 The bridge

`input_bridge.rs` maps keys through one `(winit KeyCode, KeyCode)` table and adds `translate_modifiers` and one function per input event over plain winit data, since a test cannot build a `KeyEvent` (A9): a key event, focus, modifiers, pointer leave, the scale factor. Key events follow Q3: a synthetic release is dropped; a synthetic press, which winit sends for each key still held when focus returns, marks its key with `suppress_until_release`, so X11's auto-repeat that follows is no press (A5); a press flagged `repeat` of a key not held is dropped, being a repeat of a press the engine never saw. `window_event` calls them; `resumed` sets `ScaleFactor` from `window.scale_factor()`; `App::with_plugins` inserts the default. Core stays free of winit (`D-007`).

### 2.3 R2's split

The split is the first pass of the direct order whose color or resolve target is `Swapchain`, `D-087`'s stage; a blit or direct-capture frame splits at the same index (A16). `render_frame_internal` then:

1. builds the order, choosing the present path from the armed capture without taking it;
2. uploads the camera and prepares text;
3. records passes before the split into a first encoder and submits it (Q6); with the split at 0 there is no first buffer;
4. acquires; a skip or failure returns as today, the capture dropped by `capture_for_frame`, after `post_frame` so every prepare is trimmed once;
5. if the acquire resized the targets (A15: the pool's generation or the size changed), records steps 2 and 3 again at the new size, with the timing resources rebuilt from the resized pool, since a larger size can add bloom mips, and a `debug` log line saying so (Q7). Steps 2 and 3 are one function the frame calls before the acquire and, after such a resize, once more; whether to call it again is a GPU-free decision in `surface_acquire.rs` with transition tests, where the render crate keeps acquire decisions (Q12);
6. records the rest, the direct capture's blit, the readback and the timestamp resolve into a second encoder, submits, presents and finishes as today.

The split falls on pass descriptors: a bloom slot that writes the swapchain records its threshold, downsample and upsample passes after the acquire with its composite (Q13). `begin_timed` and the bloom slot take `Option<&TextureView>` for the swapchain and panic on a `Swapchain` target without one, which the split test rules out; public `PassRecorder::begin` keeps its signature. The split helper is crate-private. The early submit sits behind one private `const`, so step 5's probe flips one token.

### 2.4 Telemetry (Q8)

`render_encode` stays the frame's whole recording, both buffers, so `gpu`'s and `gpu-throughput`'s owned metric keeps its meaning. `CpuFrameTimings::encode_pre_acquire_ms`, `FrameTimings::render_encode_pre_acquire_ms` and the `frame:` key `render_encode_pre_acquire` carry its part before the acquire; the early submit's time joins `render_submit_present`. The runner needs no change (A18).

### 2.5 Seam and template

Core gains plain types and no winit; render gains no core dependency; the extract is untouched (`D-007`, `D-018`). No template change: how a game is written does not change, and `input.json` only gains names.
