## 2. Design

- **A1's rule (Q1).** In `stage_fixed_update`'s zero-step branch, when the frame's game clock stood still while real time ran (`Time::game_delta() == 0` and `real_delta() > 0`: a pause or scale 0 as the frame started), the app clears the fixed view's edges with `InputState::end_fixed_step`, beside the existing hold that runs only while the clock advances. The predicate reads the frame's dts, not `is_paused()`, since a pre-update system that resumes the clock changes the setting mid-frame. A press reaches exactly one step while the clock runs, at any frame rate, as `D-137` says; none made on a stopped clock reaches a step, as held events do not (`D-139`). A zero-dt frame, the harness's `set_dt(0.0)`, keeps the edges: no time passed, and input has no second window as events do. Level queries, the frame view and the raw stream are unchanged. No new public item; a behaviour change with a ledger row and decision 146.
- **A2.** The pick runs in `pre_update`, after the clock stage has set this frame's `alpha` and before the steps move the bodies, so the overlay's formula would mix the new `alpha` with the old positions at an accumulator rollover. The click targets what the last frame drew, which `physics_sync` wrote into each body's `Transform`. So the collider pick tests a collider at its body's `Transform` when it has one, else at `Position`; the overlay is unchanged.
- **A6.** `contact` reads the engine's `PrevPosition`, and `move_obstacles` stops writing its own; under Q4's fallback the component is renamed `SweepStart` instead.
- **A7.** `Timer::once` for the cooldowns, immunity, control lock and the hole's lifetime (`remaining()` feeds the hole's fade), `Timer::repeating` for the HUD interval, each ticked with `Time::delta()` where the old counter subtracted it.
